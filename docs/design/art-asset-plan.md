# 界面与美术方案（围观台）

> 定位：这是一个 **LLM 对局的"围观台/评测台"**，不是玩家操作的游戏。
> 美术的首要目标 = **把 LLM 的"主观智能"变得可见**（决策理由、外交博弈、战术选择），而不是堆特效。
> 原则：**不重复造轮子**——一律用可商用/开源素材（见 `assets/art/ATTRIBUTION.md`）。
> 更新：2026-10-01

---

## 1. 路线：主推 Web
- Web（React + PixiJS）天然可分享、可直播——"电子斗蛐蛐"本质是**内容**。
- Pygame 渲染层逐步降级为**本地调试通道**，不再并行投入美术。

## 2. 信息架构（一屏）
```
┌───────────────────────────────────────────────┬──────────────────┐
│ TopBar：标题 · 回合 x/24 · 参战模型标签 · 连接态 │                  │
├───────────────────────────────────────────────┤  Panel（tab）     │
│                                               │  · 决策（★核心）  │
│           势力地图（PixiJS）                    │  · 城池          │
│   hex 地形 + 势力色 + 军队 + 迷雾 + 影响力       │  · 将领          │
│                                               │  · 外交          │
├───────────────────────────────────────────────┤  · 数据          │
│ EventTicker：事件流                            │  · 事件 / 日志    │
└───────────────────────────────────────────────┴──────────────────┘
```

**最大缺口：当前 tab 里没有「决策」——而它是灵魂。** 每回合每方产出一段"策略/决策理由"，摆出来，"主观智能"才可见。

## 3. 把"智能"可视化的功能清单（按优先级）
| 优先级 | 功能 | 说明 | 依赖 |
|---|---|---|---|
| P0 | **决策理由流** | 每回合每方一句策略，可展开看完整推理 | 需改 LLM 输出格式（见下） |
| P0 | **外交信使面板** | 势力间消息往来，已存在 `DiplomacyPanel`，需强化"关系图" | 已有 |
| P1 | **外交关系图** | 势力间箭头（盟/战/停），**背盟闪红** | 关系数据已有 |
| P1 | **战术自动识别** | 检测"坚壁清野/围魏救赵"等并打标签 | 需规则检测 |
| P2 | **名场面回放** | 城池易主、名将招降瞬间慢放 | 需事件日志 |
| P2 | **强弱曲线** | 城市/兵力/资源随回合 | 已有 log |

> ⚠️ 前置改造：当前 prompt 要求"只输出 JSON 数组"，导致 LLM 的**推理被丢弃**。要显示"决策理由"，需让模型输出 `{reasoning, commands}`（或先输出策略再输出 JSON）。

## 4. 美术风格：克制地混（A 为底，B/C 点睛）
| 方向 | 气质 | 建议用途 |
|---|---|---|
| **A 战情室/沙盘**（现状） | 专业克制、信息密度高 | **信息主体**：面板、表格、地图底色 |
| **B 水墨汉风** | 竹简/宣纸/印章/毛笔 | **点睛**：势力=印章/旗、外交=信笺、标题=宋体 |
| **C 赛博汉风** | 霓虹+汉纹+数据流 | **点睛**：名场面高亮、关键时刻 |

- 底色保持 `#1a1a2e`，金色 `#d4a84b` 做点睛；**信息区不花**，保证可读。
- ⚠️ 现势力色板里 `caocao #6b3020`、`dongzhuo #3a3040` 在深底上几乎不可见，需提亮或加描边。
