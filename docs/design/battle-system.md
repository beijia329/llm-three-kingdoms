# 战斗系统设计文档

---

## 一、战斗系统架构

### 1.1 模块划分

```
battle/
├── battle_context.py      # 战斗上下文（纯数据）
├── battle_scheduler.py    # 战斗调度器
├── army_movement.py       # 行军系统
└── battle_resolver.py     # 战斗结算器
```

### 1.2 设计原则
- **上下文共享**：所有子模块通过BattleContext传递数据，不互相持有引用
- **单一职责**：每个模块只做一件事
- **可替换**：可以单独替换战斗结算算法，不影响其他模块

## 二、行军系统 (ArmyMovement)

### 2.1 职责
- 处理军队移动
- 计算行军进度
- 处理粮草消耗
- 到达目的地后的处理

### 2.2 行军规则

#### 行军速度
- 基础速度：每回合前进1个城市距离
- 军队规模不影响速度（简化处理）
- 地形不影响速度（第一版简化）

#### 粮草消耗
```
每回合消耗 = 士兵数量 × 0.2 粮草
```

#### 断粮惩罚
- 粮草耗尽后，每回合士气下降10点
- 士气低于30%，部队开始溃散（每回合损失10%兵力）
- 士气降至0，部队全灭

### 2.4 到达处理

军队到达目的地后：
1. 如果是己方城市 → 入城，补充守军
2. 如果是敌方城市 → 开始围城
3. 如果遇到敌方军队 → 触发野战

## 三、战斗调度器 (BattleScheduler)

### 3.1 职责
- 检测哪些地方会发生战斗
- 配对攻击方和防守方
- 创建战斗上下文
- 分配多支部队的战斗

### 3.2 战斗类型

| 类型 | 触发条件 | 说明 |
|------|---------|------|
| **攻城战** | 敌方军队到达己方城市 | 有城墙，有守城方优势 |
| **野战** | 两支军队在野外相遇 | 无地形加成，纯兵力对抗 |
| **遭遇战** | 行军途中相遇 | 双方都没有准备，士气影响大 |

### 3.3 多部队战斗分配

当多支部队同时攻击一个目标时：
- 合并为一个攻击方集团
- 计算总兵力、平均士气、平均统帅
- 统一进行战斗结算

## 四、战斗结算器 (BattleResolver)

### 4.1 战斗流程

```
开始 → 战前计算 → 战斗回合循环 → 战斗结束 → 结果处理
```

### 4.2 攻城战详细流程

#### 阶段1：围城阶段
- 攻击方围住城市
- 每回合对城墙造成伤害
- 守军可以选择出击（第一版简化，自动守城）

**城墙伤害计算：**
```
城墙伤害 = 基础伤害 × 攻击方兵力系数 × 统帅加成
基础伤害 = 100 / 回合
兵力系数 = min(攻击兵力 / 守军, 3)
统帅加成 = 1 + (统帅 - 50) / 100
```

#### 阶段2：巷战阶段
城墙被打破后，进入巷战：
- 双方每回合互相造成伤害
- 防守方有城市防御加成（+30%）
- 士气影响战斗力

**伤害计算公式：**
```
基础伤害 = 己方兵力 × 0.1
统帅加成 = 1 + (统帅 - 50) / 100
士气加成 = 士气 / 100
地形加成 = 1.0（攻方） / 1.3（守方攻城）

最终伤害 = 基础伤害 × 统帅加成 × 士气加成 × 地形加成
```

#### 阶段3：胜负判定

战斗结束条件（满足任一）：
1. 攻击方兵力 ≤ 0 → 防守方胜利
2. 防守方兵力 ≤ 0 → 攻击方胜利，城市易主
3. 攻击方粮草耗尽 → 攻击方撤退
4. 攻击方士气 < 20 → 攻击方崩溃撤退
5. 战斗超过10回合 → 平局，双方撤退

### 4.3 士气系统

#### 士气变化因素

| 事件 | 士气变化 |
|------|---------|
| 每损失10%兵力 | -5 |
| 击杀敌方10%兵力 | +3 |
| 将领阵亡 | -15 |
| 断粮（每回合） | -10 |
| 以少胜多 | +10 |
| 被包围 | -8 |
| 城市被围（守军） | -3/回合 |

#### 士气效果

| 士气范围 | 战斗力 | 特殊效果 |
|---------|--------|---------|
| 90-100 | +20% | 不会溃散 |
| 70-89 | +10% | 正常 |
| 50-69 | 0% | 正常 |
| 30-49 | -15% | 有概率逃跑 |
| 20-29 | -30% | 高概率溃散 |
| 0-19 | -50% | 每回合损失10%兵力 |

### 4.4 将领作用

#### 战斗中的将领效果
- **主将**：提供统帅加成，影响整体战斗力
- **副将**：提供次级加成，主将阵亡后接替
- **将领阵亡**：部队士气大幅下降

#### 将领俘虏
- 战斗失败后，将领有概率被俘
- 俘虏概率 = f(双方兵力比, 将领忠诚度)
- 被俘将领可以被招降或斩首

## 五、战斗结果处理

### 5.1 BattleResult 数据结构
```python
@dataclass
class BattleResult:
    battle_id: str
    battle_type: str
    result: str  # attacker_win / defender_win / draw / retreat

    # 伤亡
    attacker_casualties: int
    defender_casualties: int

    # 士气变化
    attacker_morale_change: int
    defender_morale_change: int

    # 将领
    captured_generals: List[str]  # 被俘将领ID列表
    killed_generals: List[str]    # 阵亡将领ID列表

    # 城市
    captured_city: Optional[str] = None  # 被占领的城市ID

    # 战斗日志
    battle_log: List[str]
```

### 5.2 战后处理流程

#### 攻击方胜利（攻城战）
1. 城市易主
2. 守军全部被消灭或被俘
3. 守将有概率投降或被俘
4. 城市民心下降
5. 攻击方军队入城

#### 防守方胜利
1. 攻击方军队撤退
2. 攻击方损失惨重
3. 守将忠诚提升
4. 城市民心上升

#### 平局/撤退
1. 双方脱离接触
2. 攻击方返回出发城市
3. 双方都有伤亡

## 六、平衡性参数

### 6.1 战斗参数表

| 参数 | 值 | 说明 |
|------|----|------|
| 基础伤害率 | 10%/回合 | 每回合基础伤亡比例 |
| 城墙基础防御 | +30% | 守城方防御加成 |
| 统帅影响系数 | 0.01 | 每点统帅+1%战斗力 |
| 士气影响系数 | 0.01 | 每点士气+1%战斗力 |
| 最大战斗回合 | 10 | 超过则平局 |
| 溃散士气阈值 | 20 | 低于此值开始溃散 |
| 溃散损失率 | 10%/回合 | 溃散后每回合损失 |

### 6.2 调优建议
- 如果进攻方太强 → 增加城墙防御加成
- 如果防守方太强 → 增加攻城伤害，减少防御加成
- 如果战斗太快结束 → 降低基础伤害率
- 如果战斗太慢 → 提高基础伤害率
- 如果士气影响太大 → 降低士气系数
