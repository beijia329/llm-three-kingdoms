## 0. 结论速览（可直接引用块）

> **在「每个模型各坐庄一个不同势力、终局比城市数」的朴素设计下，观测到的胜负排名主要反映的是「势力开局强度」，不是「模型能力」。**
>
> 依据：在一次**决策算法相同、仅坐庄势力不同**的 100 局基线实跑中（CLIPlayer，各势力仅性格权重不同），
> 终局胜率从 **0% 分布到 32.0%**（公平份额 8.33%），**孙坚 = 3.8× 公平份额**，另有 **4 个势力 100 局 0 胜**。
> 既然「模型」在 12 个势力上是同一个算法，**这个 0%→32% 的胜率落差就几乎全部归因于开局位置**，而非决策能力。
> 把它读成「孙坚这个模型更聪明」是范畴错误。
>
> **正确做法**：比较时**固定坐庄势力 + 固定 seed**（进而固定地图、事件、对手集），使「模型决策」成为唯一自变量。

## 1. 问题一：为什么「把 12 个模型的最终城市数排序」是错的？

因为**终局指标不是「模型能力」的单变量函数**。把它写成可测量的形式：

```
终局城市数 = f( 模型决策能力 , 开局位置 , 随机序列 )
               ↑ 想测       ↑ 干扰项      ↑ 干扰项
```

朴素设计里，12 个模型分别坐庄 12 个**不同的**势力。于是「开局位置」这个干扰项**与自变量完全共线**——
每个模型配了一个不同的位置偏差。最终你排出来的，主要是**位置偏差的排序**。

**关键证据（自然实验）**：`docs/qa/acceptance-2026-10-01.md` §3.3 的 100 局基线实跑中，
**12 个势力的决策者是同一个算法（CLIPlayer）**，唯一差别是坐庄势力（及其性格权重）。
在「模型能力」这一项被**人为固定为常量**的实验里，胜率仍然：

| 势力 | 胜率 | 与公平份额之比 |
|------|------|----------------|
| 孙坚 sunjian | **32.0%** | **3.8×** |
| 汉室 / 曹操 / 刘焉 | 各 7.0% | 0.84× |
| 刘表 / 公孙瓒 | 各 5.0% | 0.6× |
| 袁术 | 3.0% | 0.36× |
| 袁绍 | 1.0% | 0.12× |
| 张角 / 董卓 / 刘备 / 马腾 | 各 **0.0%** | 0 |

> 公平份额 = 1/12 ≈ 8.33%。来源：`docs/qa/acceptance-2026-10-01.md` §3.3（quality-lead 100 局实跑，2026-10-01）。
> 该报告同时指出：孙坚 `aggression=0.6` 并非最高（董卓 0.9、张角 0.8 更高却 0 胜），
> 故指向**起始布局/邻接**而非性格。

**推理**：当「模型」被固定成同一个算法，**任何胜率落差都不可能是模型能力造成的**。
0%→32% 这个跨度，就是**开局位置能独立解释的方差下限**。
真实评测里再叠加真正的模型差异，两者混在一起、且无法分离——**排序结果不可解释**。

## 2. 问题二：错在哪个环节？开局差异如何传导到终局指标？

偏误沿一条**滚雪球链**从开局传导到终局：

```
开局位置差          → 早期扩张/存活差       → 滚雪球         → 终局指标
（守军/将领/邻接）      （先占中立/少挨打）      （城多→资源多→兵多）   （城市数/胜率）
```

**每一环都有实测支撑**：

### 2.1 环一：开局位置差（实测，`data/cities.json` / `data/generals.json`）

本会话实读初始配置（31 城，含 10 座 neutral）：

| 维度 | 极大 | 极小 | 极差 |
|------|------|------|------|
| 总守军 | 汉室 / 刘焉 **5500** | 董卓/孙坚/公孙瓒/袁术 **2000** | **2.75×** |
| 将领数 | 曹操 **8** | 刘焉 **2** | **4×** |
| 平均统帅 | 公孙瓒 82.7 | 刘表 63.2 | — |

**地理暴露度**（本会话实测：取该势力所有城的一跳邻居，按归属去重计数，方法=并集）：

| 势力 | 接壤**敌势力**数 | 接壤**中立城**数（安全扩张缓冲） |
|------|-----------------|--------------------------------|
| 孙坚 sunjian | 3 | 2 |
| 董卓 dongzhuo | 4 | **0** |
| 刘备 liubei | 5 | **0** |
| 张角 zhangjiao | 6 | 1 |
| 马腾 mateng | 6 | **0** |

> ⚠️ 与 `docs/design/balance-tuning-plan.md` §1 的口径存在差异（该表记孙坚敌邻 2、张角中立 3）。
> 差异源于「邻接」定义不同（本例为一跳并集；平衡表口径未在本文件核实）。**两表方向一致**：
> 孙坚最安全、董卓/马腾/刘备/张角最暴露。引用时请注明用的哪套口径。

**关联**：开局最安全（孙坚：低敌邻 + 有中立缓冲）与胜率最高（32%）对应；
开局最暴露（董卓/马腾/刘备/张角：0 中立缓冲且多敌邻）与 0 胜对应。

### 2.2 环二：滚雪球 → 终局指标与「全局棋盘状态」耦合（实测，`tests/balance/data/exp16_attribution.json`）

终局集中度 `top_share` 与「还剩几个势力」强耦合（本会话实读 exp16 原始 JSON）：

| 档位 | surviving（存活势力） | top_share（最大势力城占比） | 归一化 `top_share × surviving` |
|------|----------------------|---------------------------|-------------------------------|
| pre | 12.0 | 0.201 | 2.42 |
| G | 9.0 | 0.267 | 2.38 |
| C8 | 9.0 | 0.260 | 2.33 |
| C5 | 8.0 | 0.392 | 3.05 |
| C | 7.2 | 0.493 | 3.21 |

> 读法：`top_share` 从 0.201 涨到 0.493，很大一部分**不是**「强者更强」，而是分母
> （存活势力数）从 12 掉到 7 造成的（`v4-conquest-pressure.md` §4.5.1 已确认此耦合）。
> **含义**：连「最大势力占多少城」这种指标都被**全局棋盘状态**放大，
> 单看某模型的终局城市数更无法分离其贡献。

### 2.3 环三：终局结果对「非玩家参数」高度敏感（实测，exp16 同一批 seed）

exp16 在**同一批 seed（1–5）**下，只改**系统参数**（不改玩家决策），胜者集合完全换血：

| 档位 | 5 局胜者 |
|------|----------|
| pre | 袁术 / 袁术 / 袁术 / 孙坚 / 孙坚 |
| G | 张角 / 袁术 / 孙坚 / 曹操 / 公孙瓒 |
| C | 公孙瓒 / 袁术 / 公孙瓒 / 公孙瓒 / 袁绍 |
| C8 | 袁术 / 袁术 / 公孙瓒 / 公孙瓒 / 袁术 |

> 来源：`tests/balance/data/exp16_attribution.json`（本会话实读）。
> **含义**：「谁赢」是规则集 + seed 的高敏感函数。评测若不同时锁定规则集与 seed，
> 跨运行比较毫无意义。**这条同时说明：单局定胜负的样本量根本不够（见 §3.3）。**

## 3. 问题三：为什么「同 seed 同势力」能消掉这个污染？

**因为它把干扰项逐一固定成常量，只留自变量。**

| 变量 | 朴素设计 | 同 seed 同势力 | 效果 |
|------|----------|----------------|------|
| 开局位置（守军/将领/邻接） | 每模型各不同 → **共线** | **固定为同一势力 → 相同** | 消掉位置偏误 |
| 随机序列（地图/事件/掷骰） | 每局不同 | **固定同一 seed → 相同** | 消掉方差 |
| 对手集 | 不同 | **固定同一对手配置 → 相同** | 消掉对手强度差 |
| **模型决策** | 混在一起 | **唯一变量** | **这才是被测量的量** |

这就是**受控实验（paired/controlled comparison）**：终局差异**只能**归因于模型决策。

### 3.1 三种可操作的具体形式（供协议文档选）

1. **同势力对打（推荐）**：选出 1 个「基准势力」，每个模型都在**同 seed、同对手配置**下坐庄它，跑 N 个 seed，比较终局指标**分布**。
2. **轮转坐庄（公平性最强）**：每个模型轮流坐庄**全部 12 势力**，每个（模型 × 势力 × seed）组合都跑。位置偏差在**跨势力平均**后被消除——这直接对冲了「某势力天生强」。
3. **镜像对照**：模型 A 与模型 B 坐庄同一势力、同一 seed，直接配对比较（差值的方差远小于绝对值的方差）。

> 形式 1 最省算力，形式 2 最能防「模型恰好抽到好势力」的运气，形式 3 样本效率最高。
> **团队建议**：主口径用 2（轮转），单点对比用 3（镜像）。

### 3.2 必须同时固定的三件套（缺一即失效）

- **势力**（位置）、**seed**（随机序列）、**对手集**（对抗强度）。
  只固定势力不固定 seed，则 §2.3 的敏感性照样污染结果。

### 3.3 样本量（诚实说明：**部分无实测**）

- **已有实测**：100 局里，孙坚胜率 32.0% 的 **95% 置信区间为 ±9.1%**（`acceptance-2026-10-01.md` §3.3）。
  即**约 100 局才能把单势力胜率估到 ±9 个点**。若模型间真实差距小于此，就必须更大样本。
- **无实测**：**「真实 LLM 模型之间」的差距量级（signal size）没有数据**——
  本会话无 API Key、未跑 LLM 对局。protocol 文档据此定样本量前，**建议先跑一轮小样本 pilot 估 signal**，
  再用 `N ≈ (2.8 × σ / δ)²` 反推所需局数（δ=待检出的模型差距）。
- **明确建议**：不要用「单局定胜负」或「少量局排名」下结论；报告须给**分布 + CI**，不给单一排名。

## 5. 给 protocol 文档的一句话结论

> **评测的自变量是「模型」，那么势力、seed、对手集就都必须是控制变量。**
> 缺一个，「模型能力排名」就退化成「开局位置 + 随机噪声的排名」。
> 本文件给出的是**位置偏误的量级下限：0%→32% 的胜率跨度（同算法、异势力）**——
> 任何小于这个跨度的「模型差距」结论，都无法从跨势力比较中分辨出来。
