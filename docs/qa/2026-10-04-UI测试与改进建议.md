## 〇、结论先行

1. **编译与冒烟通过**：`tsc && vite build` 零错误；1920×1080 → 900×600 六档分辨率下首屏均正常渲染，**0 条 console error、0 条 page error、0 条失败请求**，无文档级溢出（scrollW == clientW）。

## 四、问题清单

> 格式：**现象 → 影响 → 定位 → 严重度 → 修改建议**
> 严重度：**高** = 阻塞性 Bug ／ **中** = 明显体验问题 ／ **低** = 优化建议

### H1 · 离线或弱网下全部图标失效（62/62）

- **现象**：阻断 `cdnjs.cloudflare.com` + `fonts.googleapis.com` 后实测，页面 62 个 `i.fa-solid` 元素**渲染尺寸全部为 0**（即图标不可见）。地图 canvas 正常，文字正常。
- **影响**：项目定位是**本地单机浏览器展示**。代理掉线、内网环境、CDN 被墙时，界面退化为"无图标"：关闭按钮变空白、tab 只剩文字、状态图标全丢。按钮语义大面积丢失。
- **定位**：`web/index.html:26-30` —— `<link href="https://fonts.googleapis.com/...Noto+Sans+SC...">` 与 `<link href="https://cdnjs.cloudflare.com/.../font-awesome/6.5.1/css/all.min.css">`
- **严重度**：**高**（是否阻塞取决于第 1 节第 2 项的确认；按"离线是真实场景"判定为高）
- **建议**（零业务改动、零视觉变化，所有 `fa-solid fa-xxx` 类名保持不变）：
  1. `npm i -D @fortawesome/fontawesome-free`；
  2. 在 `web/src/main.tsx` 顶部加 `import '@fortawesome/fontawesome-free/css/all.min.css'`；
  3. 删掉 `index.html` 里那两行 `<link>`。字体同理：`font-family` 已回退到 `"PingFang SC", "Microsoft YaHei", sans-serif`，本机直接用系统字体即可，Noto Sans SC 可直接去掉。

### H2 · 战报与事件同一条显示两个互相矛盾的回合号

- **现象**：实测战报 tab 输出 **`第12回合 第 11 回合: 4 场战斗`**、`第11回合 第 10 回合: 3 场战斗`。底部事件流同样结构：`[第N回合]` + 自带回合号的正文。
- **影响**：观众看到一条记录带两个不同回合号，无法判断战斗究竟发生在哪一回合。本项目的核心价值是"让 LLM 的主观智能可见"，时间线错乱直接损害该价值。
- **定位**：三处同样的写法——`Panel.tsx:681`（`第{e.turn}回合` + `{e.text}`）、`Panel.tsx:485`（同类）、`EventTicker.tsx:42`（`[第{evt.turn}回合]` + `{evt.text}`）。后端 `events[].text` 自带"第 N 回合"字样（实测 `{turn: 4, text: '第 3 回合: 1 场战斗'}`）。
- **严重度**：**高**
- **建议**：纯前端正则判断，不动后端。
  ```ts
  const hasTurn = /第\s*\d+\s*回合/.test(e.text)
  // hasTurn 为真时只渲染 {e.text}，不再加前缀；否则才补 `第{e.turn}回合`
  ```
  若需保留前缀语义，可改为不带数字的中性标签（如"上回合战报"），但需先确认后端语义（战斗发生在 N-1 回合、N 回合结算上报）。

### H3 · 设计 token 与硬编码色值分裂，含 2 处 WCAG 严重不达标

- **现象**：`theme/index.ts:186-188` 明确写着"#5a5a72 对深底仅约 2.8:1，远低于 WCAG AA 4.5:1，已提亮到 #8a86a0"、"#96918a 已提亮到 #a8a29a"。但源码里**旧值仍在硬编码**：
  - `#96918a`（旧 textSecondary）约 **30 处**：`Panel.tsx`(15)、`DiplomacyPanel.tsx`(5)、`DiplomacyGraph.tsx`(4)、`CityCard.tsx`(3)、`BattleOverlay.tsx`(1)
  - `#5a5a72`（**2.8:1，不达标**）**2 处**：`Panel.tsx:485`（回合号，11px）、`Panel.tsx:515`（28px 大图标）
  - `#7d7a92` **2 处**：`Panel.tsx:403`、`LlmSetupBar.tsx:199`
- **影响**：① 11px 的"第N回合"字样在深底上几乎不可读；② 主题色存在"两个事实源"，改主题必漏改——这正是 `theme/index.ts` 自己批评的问题。
- **定位**：见上。`UI_COLORS.textSecondary / textMuted` 实际只在少数几处被引用。
- **严重度**：**高**（`#5a5a72` 那 2 处）／中（其余一致性）
- **建议**：批量替换，`#5a5a72` / `#7d7a92` → `UI_COLORS.textMuted`（#8a86a0）；`#96918a` → `UI_COLORS.textSecondary`（#a8a29a）。**颜色值本身不变视觉**（就是阶段 A 已确认的那套），只是消灭硬编码。可先用 `theme` 已有 token 全量替换，再跑一次构建确认无误。

### M4 · 右侧面板在 ≤1600×900 全部需要滚动，12 方势力看不全

- **现象**：实测面板内容固定 940px，可视高度随视口缩水，需滚动量：1600×900 → 112px，1366×768 → 244px，1280×720 → 292px，1024×640 → 372px，900×600 → 412px。仅 1920×1080 可全见。
- **影响**：12 方势力是本作核心信息，主流笔记本（1440×900 / 1366×768）开局就看不到后 2–4 个势力，且界面无任何"还有 N 方"的提示。
- **定位**：`Panel.tsx` `styles.container` `width: 300px` + `styles.content` `overflowY: auto`（滚动本身已实现，问题在信息密度）
- **严重度**：**中**
- **建议**：二选一，均不动数据结构：
  1. **势力卡改双列**（每卡约 140px 宽），12 方 6 行即可在 768 高度全见；
  2. 保留单列，在面板顶部加一行计数条"共 12 方 · 向下滚动查看"，消除"以为只有 8 方"的误判。

### M5 · 浮层右边界四个硬编码魔数互不对齐

- **现象**：面板实宽 300px，但四个浮层各用各的偏移——`TopBar.tsx:65` `right: 324px`、`EventTicker.tsx:60` `right: 330px`、`App.tsx:288`（下一回合按钮）`right: 318px`、`App.tsx:306`（自动推进条）`right: 470px`。
- **影响**：① 顶栏、底栏、按钮右边界最大差 12px，视觉上明显不对齐；② Panel 宽度一改，四处全部错位（典型的"改一处崩一片"）。
- **定位**：见上四个文件行号。
- **严重度**：**中**
- **建议**：在 `theme/index.ts` 加 `export const PANEL_W = 300`，四处改为 `right: PANEL_W + 24`（建议统一用 24：顶栏 324、事件流 324、下一回合 324、自动推进条 324+140+12=476）。一次性消灭魔数。

### M6 · 「重开一局」无二次确认，点击即清空整局进度

- **现象**：实测按钮只有 `title="按当前模式与参战势力重新开局（会清空当前进度）"`，无任何确认弹层，点击直接 `POST /api/reset`。
- **影响**：本地单机、无存档回滚。误点一次 = 当前 48 回合进度全部丢失且不可撤销。
- **定位**：`LlmSetupBar.tsx` 重开按钮（上一轮审计 §3-7 已提出，本次实测仍未修）
- **严重度**：**中**
- **建议**：复用现有 `ShortcutHelp.tsx` 的弹层样式做一个确认框："重开会清空当前进度，确定？[取消] [确定重开]"。不新增组件体系，视觉风格统一。

### M7 · thinking 状态两处重复渲染，且 CLI 模式下文案错误

- **现象**：`App.tsx:168-174` 与 `LlmSetupBar.tsx:355-363` **同时**绑定同一个 `thinking` 状态，都渲染倒计时。其中 `App.tsx:172` 硬编码"（LLM 单回合约 30 秒）"，但实测 **CLI 规则 AI 模式单回合 <120 ms**。
- **影响**：① 同一信息两处重复（文案还不一样："AI 思考中 · 已等待 Ns" vs "AI 正在思考中（约 30 秒） 已等待 Ns"）；② 规则 AI 模式下告诉用户"约 30 秒"是错误预期。
- **定位**：`App.tsx:168-174`；`LlmSetupBar.tsx:355-363`（后者已按 `mode === 'llm' || llmActive` 正确区分文案）
- **严重度**：**中**
- **建议**：**删掉 `App.tsx` 的 thinkingBar**，保留 `LlmSetupBar` 那条（信息更完整且已做模式区分）。若坚持保留顶部提示，至少把"（LLM 单回合约 30 秒）"改为按 `llmActive` 条件渲染。

### M8 · 可点击元素只有光标变化，无 hover 反馈

- **现象**：`Panel.tsx` 有 **5 处 `cursor: 'pointer'`，0 处 `onMouseEnter` / `:hover` / `onMouseDown`**。势力卡、城市项、武将项点击前后视觉完全一致。
- **影响**：观众无法预判"这个能不能点"、"我点到哪一个了"。对比 `CityCard.tsx` 做得完整（hover 之外还有 disabled 0.45 透明度 + busyLabel + 成功/失败回显），面板侧明显落后。
- **定位**：`Panel.tsx:104`（势力卡）、`:198`（城市项）、`:727`、`:762`、`:848`
- **严重度**：**中**
- **建议**：统一给这 5 类卡片加 hover 态，背景由 `rgba(255,255,255,0.03)` → `rgba(255,255,255,0.07)`，配合已有的 `transition: 'all 0.2s ease'`。可抽成 `styles.cardHover` 复用。

### L9 · 事件 tab 连续零事件平铺，信息密度低

- **现象**：实测事件 tab 输出 10 行几乎相同的内容："第 11 回合 186年 0 战斗 0 行军"、"第 10 回合 … 0 战斗 0 行军"……
- **影响**：有效信息为零，却占满整屏，把真正有价值的事件挤到看不见。
- **定位**：`Panel.tsx` `EventsPanel`
- **严重度**：**低**
- **建议**：把连续的零事件段折叠为一行"第 2–11 回合：无战事"，有事件的回合照常展开。

### L10 · 首帧 `/api/state` 仍达 2.34 MB

- **现象**：实测首帧 2,339,656 B，`hex_map` 24000 格占约 98%。版本指纹与增量机制**已生效**（`?hex_map_version=` 已支持），但首帧与断线重连仍走全量。
- **影响**：首屏加载与重连时的明显卡顿窗口。
- **定位**：`api/game_manager.py:455` `_hex_map_payload()`；前端 `useGame.ts:130` `fetchHexMap`（兜底函数已存在）
- **严重度**：**低**（已有增量机制，属收尾优化）
- **建议**：首帧让 `/api/state` 不携带 `hex_map`，由前端用**已存在的** `fetchHexMap()` 单独拉 `/api/hex_map`。前端改动极小（兜底路径已验证可用）。

### L11 · PixiJS 打包 543 KB，三种 renderer 全量进包

- **现象**：实测产物 `WebGLRenderer` 68.88 kB + `WebGPURenderer` 39.09 kB + `CanvasRenderer` 18.03 kB **全部**打进 dist，主 chunk 543.48 kB（gzip 174.52 kB），触发 Vite 500 kB 警告。运行时只会用到其中一种。
- **定位**：`web/vite.config.ts`（无 manualChunks 配置）
- **严重度**：**低**
- **建议**：优先用 `build.rollupOptions.output.manualChunks` 把 pixi 单独拆 chunk（利用浏览器缓存）；改按需引入Pixi 子系统收益更大但改动面广，不优先。

### L12 · 900×600 时顶栏被压缩到 264px

- **现象**：顶栏宽度 = `vw - 324 - 12`。实测 900×600 时仅 264px，内部要放标题 + 5 个势力统计。
- **影响**：极窄窗口下顶栏内容挤压。（低于常规桌面尺寸，需先确认第 1 节第 3 项）
- **定位**：`TopBar.tsx:64-65` `left: 12px; right: 324px`
- **严重度**：**低**
- **建议**：确认最小分辨率下限后，若需支持 ≤1024 宽，给 `styles.stats` 加 `flexWrap: 'wrap'` 或按视口宽度动态减少展示的势力数（5 → 3）。

## 五、环境异常（建议你处理）

`127.0.0.1:8000` 上存在一个**残留的旧后端进程**（实测无法用 `ps` 查其启动时间，沙箱限制）。实证差异：

```
8000（残留旧进程）：/api/state 返回 25 字段，无 season、无 hex_map_version，turn=14
8100（v4.1.2 当前代码）：/api/state 返回 27 字段，season='spring'，turn=1
```

**后果**：连 8000 会得到错误结论。我最初的测试就因此误判"季节未修复"，改用 8100 后确认已正常。**建议**：确认该进程（`lsof -nP -iTCP:8000 -sTCP:LISTEN`）是否为废弃进程，若是则停止，避免后续开发/测试连错。
