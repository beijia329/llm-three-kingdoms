## 2. 🔴 M2 —— emoji 已去，但**替换图标渲染失败（实心色块）** → FAIL

### 症状（截图）
- **终局结算卡图标**：应显示王冠/攻城塔/天平/握手**剪影**，实际是 **44×44 的纯色实心方块**（`standard48/08-结束界面.png`、`A1-unification.png` 均可见，颜色=势力色）。
- **战斗回放标签**：`攻 … ⚔ … 守` 的 ⚔ 分隔符同样为**色块**（`m2-m4/M2c-战斗回放标签-特写.png`）。
- **地图城池剪影**：城池标记是**纯色方块 + 单字徽标**，并未渲染宫殿/堡垒剪影（`m2-m4/M2a-地图城名-特写.png`）。

### 根因（已定位到具体机制）
生产构建下，Vite 把 <4KB 的 SVG **内联为 data URI**，而该 URI 里保留了 SVG 的**单引号属性**（`xmlns='http://...'`）。代码把 URL 拼进**未加引号的 `url()`**：

```css
mask-image: url(data:image/svg+xml,%3csvg%20xmlns='http://www.w3.org/2000/svg'...)  /* ❌ 未加引号 + 内含单引号 → 非法 */
```

CSS 规范：未加引号的 `url()` **不允许**出现引号 → 该声明非法 → **浏览器直接丢弃 `mask-image`** → 元素按 `background-color` 渲染 → **实心方块**。

**实测证据（本机 Chrome，spec 级，非 headless 特有）**：
- `CSS.supports('mask-image', url(<该dataURI>))` → **false**
- `el.style.maskImage = 'url(<uri>)'` → **DROPPED**（DOM 里根本没有该属性）
- `el.style.maskImage = 'url("<uri>")'`（加双引号）→ **SET** ✅
- 转储城池 mask span 内联样式：只有 `mask-size/repeat/position`，**没有 `mask-image`**。

> 说明：dev（`vite dev`）下 SVG 是普通路径 URL，`url()` 合法 → mask 生效；**只有生产构建（内联为 data URI）会坏**。这解释了为何在开发预览里"看起来正常"。

| 文件:行 | 用途 |

| `web/src/components/GameOverOverlay.tsx:59-60` | **终局图标（本轮新增）** |
| `web/src/components/map/BattleOverlay.tsx:17-18` | 战斗标签 ⚔ 分隔符（本轮新增） |

### 建议修复（任一，推荐 ①）
1. **给 url 值加引号**：`maskImage: \`url("${iconUrl}")\``（`WebkitMaskImage` 同）—— 6 处 `.tsx` 一次改；成本最低。
2. 或 `build.assetsInlineLimit: 0`（`web/vite.config.ts`）让 SVG 走文件 URL。
3. 或把图标从 CSS mask 改为 `<img src>`。

修完请**在生产构建**（`npm run build` + 后端托管）复验——dev 预览看不出来。
