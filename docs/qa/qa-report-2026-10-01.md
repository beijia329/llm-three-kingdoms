## 2. 执行命令（真实执行）

### 2.1 主测试套件（实际执行）
```bash
cd /Users/dongsheng/Documents/llm-sanguo-project
export SDL_VIDEODRIVER=dummy
venv/bin/python -m pytest tests/unit tests/integration tests/test_gui_smoke.py \
  -q --tb=short -rA -p no:cacheprovider
```
> 说明：主理人给定命令含 `tests/balance`，但该目录不存在。实测确认 pytest **不会因缺失路径报错**，而是静默跳过并照常跑 `unit+integration+test_gui_smoke`。前台因 shell 超时上限（约 2 分钟）曾 SIGTERM（退出码 137），**非测试失败**；故改以有效子集实跑（见 2.2 复现结论）。本命令为最终有效执行命令，结果见第 3、4 节。

### 2.2 给定命令的复现（确认缺失路径行为）
```bash
venv/bin/python -m pytest tests/unit tests/integration tests/balance -q
```
实测：开始收集 unit+integration 用例并打印进度点，**未因 `tests/balance` 缺失而报错**；仅在更短的前台超时下被 SIGTERM。结论：缺失 `tests/balance` 不影响其余用例收集与执行，但**该目录的用例数为 0**，即"平衡测试"实际无内容。

### 2.3 覆盖率（真实实跑，分批）
全量 `tests/ --cov=game --cov=players.llm` 单次跑在本环境后台时限（≈14 分钟）内被 kill，无法一次产出。改为**按单元测文件分两批并行**跑覆盖率（各写独立 `COVERAGE_FILE`），最后 `coverage combine` + `coverage report`：
```bash
# 批次 B（13 文件，含 players.llm 全量 + 多 game 系统）
export COVERAGE_FILE=.../.coverage.unitB
venv/bin/python -m pytest <13 个 unit 文件> --cov=game --cov=players.llm -q --cov-report=
# 批次 C（13 文件，引擎/战斗/外交/城池等重型逻辑）
export COVERAGE_FILE=.../.coverage.unitC
venv/bin/python -m pytest <13 个 unit 文件> --cov=game --cov=players.llm -q --cov-report=
# 合并与报告
venv/bin/coverage combine .coverage.unitB .coverage.unitC
venv/bin/coverage report --show-missing --sort=cover
```
> 集成测 `tests/integration/test_full_game.py` 因覆盖率插桩下极度变慢（仅 6 个用例跑 >5 分钟未结束）**被迫放弃采集**；详见第 6 节。

## 4. 失败清单与 Traceback（真实前 20 行）

### 失败 1 — `tests/test_gui_smoke.py::test_gui_renders_one_frame`
**严重度**：Major（测试环境缺口，非引擎逻辑缺陷）
**根因**：测试用例第 42 行 `import numpy as np`，但 `numpy` 既不在 `requirements.txt`，也未装在 venv 中。

真实 traceback：

**分类**：测试基础设施依赖缺口。修复方向：将 `numpy` 加入 `requirements.txt` 并 `pip install`；或将测试改为使用 pygame 原生像素接口（如 `surf.get_buffer()` / `surf.get_at()`）避免引入 numpy。

### 失败 2 — `tests/test_gui_smoke.py::test_panel_renders`
**严重度**：Critical（**真实产品代码缺陷**）
**根因**：`renderer/game_renderer.py` 仅定义了 `FONT_CJK` / `FONT_CJK_SM` / `FONT_CJK_LG`（第 54–75 行），但第 321 行 `_draw_panel()` 引用了**从未定义的 `FONT_CJK_XS`**。该缺陷会在真实 GUI 运行到面板（含标签页）渲染时抛出 `NameError` 崩溃。

真实 traceback：
```
______________________________ test_panel_renders ______________________________
tests/test_gui_smoke.py:99: in test_panel_renders
    gr._draw_panel()
renderer/game_renderer.py:321: in _draw_panel
    draw_text(self.screen, label, bx + (tab_w - 2) // 2, 12, c, FONT_CJK_XS, center=True)
                                                                ^^^^^^^^^^^
E   NameError: name 'FONT_CJK_XS' is not defined
------------------------------ Captured log call -------------------------------
WARNING  renderer.game_renderer:game_renderer.py:76 未找到中文字体，使用默认字体
```
**分类**：代码缺陷（renderer 层）。影响：Phase 6 GUI 验收中"UI 信息面板 / 外交消息显示"等会因面板渲染崩溃而**无法通过**。修复方向：补充定义 `FONT_CJK_XS`（如 `pygame.font.Font(None, 11)` 或对应 CJK 字号），或将引用改为已存在的 `FONT_CJK_SM`。

> 附加观察：日志中 `WARNING 未找到中文字体，使用默认字体` 表示当前环境无 CJK 字体，文本渲染回退为默认字体——影响中文显示观感，但**不是**上述两个失败的直接原因。
