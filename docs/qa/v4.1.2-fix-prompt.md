### A1. 命令层统一归属权校验【核心，一次修 3 个越权漏洞】

**根因**：`game/engine.py` 的 9 个 `_execute_xxx` 各写各的归属校验，`develop / recruit / attack(异地分支)` 有，
`explore / reward / attack(同城路径)` 没有。没有统一入口，漏一个没人发现。

**要求**：在 `game/engine.py` 加一个模块级（或私有方法）的统一校验函数，例如：

    def _assert_owns(actor: str, owner, what: str, cmd_type: str):
        """归属权校验：owner 为空（中立/无主）或与 actor 不符时返回失败的 CommandResult，否则返回 None。"""

然后在下列位置接入：

| 编号 | 位置 | 现状 | 要求 |
|---|---|---|---|
| A1-a | `game/engine.py:623-650` `_execute_reward` | 全程不判断 `general.faction == cmd.faction`；**支付城市由 `general.location` 反推**（632-638 行），逻辑是"谁被赏赐花谁所在城的钱" | 取到 general 后校验 `general.faction == cmd.faction`；取到 city 后校验 `city.faction == cmd.faction`。两道都要 |
| A1-b | `game/engine.py:652-690` `_execute_explore` | 全程只查 `city is None`（655 行），无归属校验 | 在 `city is None` 之后补 `city.faction != cmd.faction` 校验 |
| A1-c | `game/engine.py:529-559` `_execute_attack` | 541-546 的 `general.faction == cmd.faction` 与 `not general.is_captured` **只写在 `if general.location != from_city.id:` 的调将分支内部**；将领恰好在出发城时这两条被整个跳过 | 把这两条校验**提到 `!=` 判断之外**做统一前置，不要依赖"是否需要调将"这个偶然条件 |

**这三个缺陷已实跑复现**（见第 4 节脚本），不要怀疑其真实性，直接修。

### A4. WS 处理器异步化

**位置**：`api/server.py:250`（auto_loop）、`api/server.py:289`（command 分支）、`api/server.py:294`（next_turn 分支）
**现状**：三处都在 `async def` 里直接调用**同步**的 `_manager.process_turn()`；
全仓搜索 `run_in_executor` / `to_thread` **零命中**。
`api/game_manager.py:141-143` 自述「LLM 模式下单回合 12 方约 40 秒」。

**影响**：这 40 秒里 asyncio 事件循环完全停摆——点「停止自动推进」要等一整个回合、ping/pong 无响应、
同进程其它请求排队饿死。

**要求**（来源：静态确认，未在浏览器实跑，请在改完时顺带用真实 LLM/慢模式实测一次）：
    loop = asyncio.get_running_loop()
    await loop.run_in_executor(None, _manager.process_turn)

  没有任何 `useEffect` 依据 `state.game_over` 复位 `auto`
- `web/src/App.tsx:139`（已在 `667bb6e` 上复核）：
  `disabled={auto || thinking}`，`connected` 未参与判定；
  同文件 135-136 行的 opacity/cursor 也是同一套条件
- 注：`App.tsx:43-44` 已有一条 `if (!state?.game_over) setGameOverDismissed(false)`，
  那是控制「终局弹窗是否关闭」的，**与复位 auto 无关，别把它误当成已修复**
- `web/src/hooks/useGame.ts:346-353` `nextTurn`：有 pending 幂等守卫，但**不检查连接状态**；
  而 `send()`（295-299 行）在 `readyState != OPEN` 时**静默 return**
- `TURN_TIMEOUT_S = 240`（useGame.ts 顶部）

**后果**：界面永久显示「自动推进中」，而「下一回合」「空格」因 auto 恒真被永久禁用，后端其实一步没在推进。

**要求**：
1. 后端 break 前发 `{"type": "auto_stopped"}`（或等价事件）。
2. 前端 `onopen` 时按当前 `auto` 补发一次 `{type:'auto', enabled:auto}`。
3. `useGame` 加 `useEffect(() => { if (state?.game_over) setAuto(false) }, [state?.game_over])`。
4. `nextTurn` / `runCommand` 入口前置 `if (!connected)` 提示并返回，不清空 UI 状态。
5. `App.tsx:139` 的 disabled 判定把 `connected` 纳入，并对不可用原因给出可见说明（不要只置灰不写字）。
