### 🕳️ 三条「定义了但从未执行」的链路

这一版最集中的问题不是功能缺失，而是已经写好的机制在生产环境从未运行——而且单测全绿、无人察觉。三例各自独立：

- **城市的民心自然变化**（四条规则全灭）
  根因：`update_city` 被放在资源产出循环的 `else`（无六角地图）分支，而生产恒有地图，恒走 `if`（`calculate_resources`）分支。被整段跳过的是围城 −3 / 断粮 −5 / 粮草盈余 +1 / 民心向 50 回归（最后一条是全局唯一的自校正项）。后果：民心除「文化发展」这一主动操作外只降不升——被打过的城永远爬不起来。
  实测（`tests/balance/exp18_*.py`，5 局 × 48 回合）：修复前该函数调用数 0，修复后 7440（= 城市数 × 回合数 × 局数，与阳性对照逐位相同）。修法：新增相位钩子 `city_morale` 挂 `AFTER_MOVEMENT`（`is_besieged` 只在行军写入与战斗清 0 之间为真，放产出相位则恒为 False）。平衡影响温和：战斗场次 389→387（−0.5%）、存活势力均值 8.80→9.40。
- **俘虏 / 投降 / 降将转投**（生产链路零测试保护）
  `resolve_battle` 调用 `process_aftermath` 时传的 `defender_generals=` 是唯一接线。实测：把它注释掉后跑 `tests/unit + tests/integration` → 631 passed, 0 failed，即摘掉它 CI 也不报警。已补生产链路回归守卫 `tests/integration/test_capture_chain.py`，并做改坏验证：改坏 → 2 failed（`captured_generals == []`），还原 → 2 passed。
- **外交消息投递**（实验台与产品不等价，属测量口径问题）
  `receive_message` 全仓只有 1 个生产调用点（`main.py:136`）；`tests/balance/pacing_lib.py` 与 `api/game_manager.py` 都不投递。后果：实验台驱动的全部平衡实验都在一个「启发式玩家不可能结盟」的世界里运行——外交消息照发（560 条/5 局），结盟提议 0 次、同盟 0 对。两变体实测（`tests/balance/exp19_*.py`）：不投递同盟 0；投递同盟 47 对（阳性对照战争对 175/175 命中）。已给实验台补上投递并与产品路径对齐。

### 🎥 围观台可读性

- 战斗可视化：进攻箭头（多出发城各一条；约 15% 的战斗是多出发城）、逐场回放、目标城常驻结果环（四态用颜色 × 线型 × 图标三重编码）、回放标签显式「攻方 ⚔ 守方」。箭头采三层描线（暗 casing + 势力色主线 + 亮芯），以同时适应羊皮纸底与深色势力填充。
- 外交关系图：环形关系图（非中立关系连线，颜色 = 战/盟/和）+ 12×12 完整矩阵（全部 66 对都能定位）+ 点选势力聚焦。修掉观战摘要取 `slice(0,12)` 导致摘要全是「汉室↔X」看不出战局的问题。
- 三处实测坑已写进代码注释：`neutral` 会作为关系一方混成「第 13 个节点」；`neutral` 既是势力 id 又是状态值；开局 66 对全中立（默认不画，避免满屏灰线）。
