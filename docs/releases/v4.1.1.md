**主题：修掉两处「能跑但不生效」的坑**

### 🔧 Web 规则-AI 模式无法结盟

- `api/game_manager.py` 新增 `_deliver_message()`，在两处命令执行点（手动命令、回合推进中的决策执行）把外交消息投递给目标玩家对象，与 `main.py:134-136` 的 CLI 路径口径一致。
- 根因：`CLIPlayer` 只能靠 `receive_message` 回调得知「有人提议结盟」（`cli_player.py:71-77` 做关键字匹配并设 `_pending_alliance`）。回调不投递，该状态恒为 `None`，结盟提议永不发出——规则-AI 在结构上不可能结盟。此前三条路径里只有 CLI 投递，Web 与实验台都不投递（实验台已在 4.1.0 修）。
- 实测（`tests/balance/exp19_diplomacy_reachability.py`）：不投递同盟 0 对；投递同盟 47 对 / 提议 92 次（阳性对照战争对 175/175 命中）。
- 守卫 `tests/integration/test_web_message_delivery.py`（5 例），并做改坏验证：注释掉投递调用，同盟断言变红；还原后 5 passed。
- Web 的 LLM 模式一直不受影响（`LLMPlayer` 走 `observation.received_messages`）。

### 🛡️ 封掉「读档」的静默降级陷阱

- `GameEngine.load_state_snapshot` 改为显式抛 `NotImplementedError`，原实现移入 `_load_state_snapshot_legacy` 留档。
- 原因：它是「只写不读」的半个功能（全仓零调用者），且实现只重建了 `rng` 与 `map`。实测（`tests/balance/exp20_snapshot_restore.py`）：

      原引擎：turn=13  hex_map=已建  season=WINTER  外交关系=69 条
      恢复后：turn=13  hex_map=None  season=SPRING  外交关系=None
      继续推进 12 回合 → 表面"成功"
      但后台抛 AttributeError: 'NoneType' object has no attribute 'set_status'
      （被引擎的命令级 try/except 吞掉）

  危险的不是它坏，是它不报错——会造出一个看起来还行、实际静默降级的引擎。按本项目「拒绝静默兜底」的原则，改为显式不可用。
- 根因是存档格式缺字段，不是接线漏了：`GameState` 只有 11 个字段，无地图/领地、无外交关系。易混点：`faction_relations` 属于 `GameObservation`（喂 AI 的观察），不是 `GameState`（存档快照）。要做存档/读档必须先扩格式，属功能开发。
- 守卫 `tests/unit/test_engine_snapshot_guard.py`（4 例）：断言显式拒绝、留档实现带停用标注、快照字段数锁定为 11（将来扩格式时会红，提醒重估可行性）。

### 📌 记录在案（未改代码）

- 停战（truce）没有任何代码能创建它。生产环境设置外交状态只有 3 处（`_execute_propose_alliance` → ALLIANCE、`_execute_declare_war` → WAR、占城时 → WAR），命令类只有 9 种，没有「停战/求和」这一类。而整套配套设施齐全：枚举、`DIPLOMACY_TRUCE_DURATION`、`truce_end_turn` 维护与到期清理、`is_truce()`、提示词的「和」标签、关系图渲染，以及 `engine.py:567`「不能攻击同盟或停战中的势力」的攻防规则。连带后果：那条攻防规则从未生效。这是缺一个触发入口（加停战命令，或删掉这套设施），需产品决策。
