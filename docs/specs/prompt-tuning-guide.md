# Prompt 调优指南

> 本文档说明如何编写和优化LLM玩家的Prompt，让AI表现更好。
> 参考：llm-integration.md 第三章 Prompt构建

---

## 一、Prompt 结构总览

一个好的Prompt由以下几部分组成，按重要性排序：

```
1. 角色设定（你是谁）
2. 目标任务（你要做什么）
3. 游戏规则（怎么玩）
4. 命令格式（怎么输出）
5. 当前状态（现在的情况）
6. 历史记忆（之前发生了什么）
7. 思维链引导（怎么思考）
```

## 二、系统 Prompt 编写技巧

### 2.1 角色设定
**要点**：给AI一个清晰的身份，让它进入角色。

**好的例子**：
```
你是三国时期的顶级军师，为你的势力出谋划策。
你精通战略战术，善于权衡利弊，能够在复杂局势中做出最优决策。
你的目标是帮助你的势力统一天下。
```

**不好的例子**：
```
你是一个游戏AI。
```

**为什么**：
- 角色越具体，AI的行为越一致
- 军师身份暗示了"理性、策略、权衡"的行为模式
- 避免AI用"我是AI"的视角思考

### 2.2 目标设定
**要点**：明确告诉AI胜利条件，以及什么是好的表现。

**好的例子**：
```
你的目标是在24回合内占领尽可能多的城市。
- 城市最多的势力获胜
- 如果城市数相同，比较总兵力
- 平局进入加时赛，每回合自动增兵
```

**注意**：
- 不要只说"赢"，要说明怎么算赢
- 不要给太多目标，优先级要清晰
- 避免"既要...又要..."的模糊目标

### 2.3 规则说明
**要点**：简洁、准确、结构化。

**原则**：
- 只说AI决策需要知道的规则
- 用列表，不要用大段文字
- 重要规则加粗或重复
- 给出数值，不要说"很多""很少"

**好的例子**：
```
## 核心规则
1. 每回合你可以执行1个命令
2. 城市每回合产出金钱和粮草
3. 民心影响产出倍率（民心100 = 产出x2.0）
4. 进攻需要行军，距离越远时间越长
5. 军队断粮会士气下降，士气为0会溃散
```

**不好的例子**：
```
这个游戏有很多资源，包括金钱、粮草、人口什么的，城市会产出这些资源，
你可以用这些资源来征兵、发展城市，然后去攻打别人的城市...
```

## 三、状态序列化技巧

### 3.1 为什么要优化状态展示
- Token是钱，展示越紧凑越省钱
- AI注意力有限，关键信息要突出
- 信息太多AI会忽略重要的

### 3.2 表格化展示
**原则**：能用表格就不用列表，信息密度更高。

**好的例子**：
```
## 我方城市
| 城市 | 等级 | 守军 | 金钱 | 粮草 | 民心 | 将领 |
|------|------|------|------|------|------|------|
| 许昌 | 3    | 5000 | 2000 | 3000 | 80   | 曹操 |
| 洛阳 | 2    | 3000 | 1500 | 2000 | 70   | 司马懿 |
```

**不好的例子**：
```
我方城市有许昌，等级3，守军5000，金钱2000...
还有洛阳，等级2，守军3000...
```

### 3.3 缩写与简化
**原则**：常用术语可以缩写，上下文清楚的情况下不影响理解。

**例子**：
- 金钱 → 金
- 粮草 → 粮
- 民心 → 心
- 统帅 → 统
- 政治 → 政
- 勇武 → 武
- 智力 → 智

**注意**：
- 第一次出现时可以标注全称
- 缩写要统一，不要一会用全称一会用缩写
- 不要过度缩写，导致AI看不懂

### 3.4 信息分层
**原则**：重要的放前面，次要的放后面，AI注意力前重后轻。

**优先级排序**：
1. 我方核心信息（城市、兵力、资源）
2. 敌方关键信息（相邻城市、敌军动向）
3. 我方次要信息（将领详情、民心等）
4. 敌方次要信息（远处的城市）
5. 历史信息（之前发生了什么）

### 3.5 信息迷雾
**原则**：只给AI能看到的信息，不要开上帝视角。

**为什么**：
- 公平，和人类玩家一样的信息
- 增加策略深度（侦查、探路）
- 避免AI用"全知视角"作弊

**迷雾规则**：
- 己方城市：完整信息
- 相邻城市：基本信息（守军、将领）
- 远处城市：只有归属和大致兵力范围
- 敌方军队：只有位置和大致数量

## 四、思维链引导

### 4.1 为什么要引导思维链
- 让AI先思考再决策，质量更高
- 思考过程可以用来调试和分析
- 强迫AI考虑多个方面，不会漏东西

### 4.2 思考框架
给AI一个固定的思考框架，让它按步骤分析。

**例子**：
```
在做出决策前，请先分析：

1. 当前局势评估
   - 我方实力如何？
   - 敌方实力如何？
   - 谁强谁弱？

2. 机会与威胁
   - 有什么可以抓住的机会？
   - 有什么需要防范的威胁？

3. 可选方案
   - 列出3个可能的行动
   - 每个的优缺点是什么？

4. 最终决策
   - 选择哪个方案？
   - 为什么？
```

### 4.3 注意事项
- 思考过程不影响游戏，只是让AI自己理清思路
- 思考过程会消耗token，太长会增加成本
- 可以根据模型能力调整思考深度
- 简单模型可能不会认真思考，只是随便写

## 五、输出格式控制

### 5.1 明确格式要求
**要点**：说清楚输出什么格式，给例子，强调"只输出JSON"。

**好的例子**：
```
## 输出格式
你必须只输出一个JSON对象，不要任何其他内容。
不要解释，不要废话，不要markdown，只要纯JSON。

JSON格式：
{
  "command": "attack",
  "params": {
    "from": "许昌",
    "to": "洛阳",
    "troops": 5000
  }
}

合法的command类型：develop, recruit, attack, reward, explore, message, rumor
```

### 5.2 常见问题

**问题1：AI输出太多废话**
**解决**：
- 强调"只输出JSON，不要其他内容"
- 在结尾重复一遍
- 用"记住：只输出JSON"这样的提醒

**问题2：AI输出的字段名不对**
**解决**：
- 给出完整的例子
- 列出所有合法的字段
- 用枚举限制可选值

**问题3：AI输出多个JSON**
**解决**：
- 强调"只输出一个JSON对象"
- 解析时取第一个或最大的

## 六、常见问题与调优方法

### 6.1 AI太保守，只发展不打仗
**可能原因**：
- 道德约束（觉得打仗不好）
- 风险厌恶（怕输）
- 没意识到进攻的收益

**调优方法**：
1. 强调"这是游戏测试，与现实无关"
2. 明确说"进攻是获胜的必要手段"
3. 给出进攻的收益例子
4. 降低进攻的风险感

### 6.2 AI有历史刻板印象（蜀吴联合打魏）
**可能原因**：
- 三国演义的影响
- 训练数据里的历史知识

**调优方法**：
1. 强调"不用遵从历史，这是独立的游戏"
2. 强调"根据当前局势决策，不要受历史影响"
3. 用中立的势力名称（比如红方/蓝方/绿方）

### 6.3 AI记不住之前的决策
**可能原因**：
- 上下文太长，信息被淹没
- 没有突出关键信息
- 记忆组织得不好

**调优方法**：
1. 优化记忆结构，重要的放前面
2. 用摘要代替完整历史
3. 突出上回合的决策和结果
4. 减少无关信息

### 6.4 AI总是犯同样的错误
**可能原因**：
- 没有从历史中学习
- 反馈不明确
- 不知道为什么错了

**调优方法**：
1. 在记忆里加上"上次决策的结果"
2. 明确指出"上次的XX决策导致了XX后果"
3. 引导AI反思之前的决策

### 6.5 AI输出格式总是错
**可能原因**：
- Prompt里的格式要求不明确
- 模型能力不够
- 例子不够清楚

**调优方法**：
1. 强化格式要求，重复强调
2. 给出更多例子
3. 用更简单的格式
4. 增加解析容错（见输出解析防御体系）

## 七、Prompt 测试与迭代

### 7.1 A/B 测试
**方法**：
- 两个版本的Prompt
- 用同一个模型
- 各跑N局
- 对比胜率和表现

**注意**：
- 控制变量，只改一个地方
- 样本量要足够（至少100局）
- 不仅看胜率，还要看行为模式

### 7.2 调优步骤
1. **基线测试**：用当前Prompt跑N局，记录数据
2. **假设问题**：分析表现不好的地方，假设原因
3. **修改Prompt**：针对假设的问题修改
4. **对比测试**：新旧Prompt各跑N局
5. **分析结果**：看有没有改进，改进是不是因为修改
6. **采纳或回滚**：有改进就采纳，没有就回滚

### 7.3 评估指标
**量化指标**：
- 胜率
- 平均存活回合
- 平均占领城市数
- 资源利用率
- 命令格式错误率

**定性指标**：
- 决策是否合理
- 有没有明显的蠢操作
- 策略是否多样
- 会不会从错误中学习

## 八、不同模型的Prompt差异

### 8.1 强模型 vs 弱模型
**强模型**（Claude Opus, GPT-5等）：
- 可以给更复杂的规则
- 可以引导深度思考
- 格式遵守更好
- 可以处理更长的上下文

**弱模型**（小模型、开源模型）：
- 规则要更简单
- 格式要求要更明确
- 思考链可能没用
- 上下文要更短

### 8.2 不同模型的偏好
- **Claude**：喜欢详细的说明，推理能力强
- **GPT**：格式遵守好，指令跟随强
- **Gemini**：多模态好，文本一般
- **国产模型**：中文理解好，但格式可能差一些
