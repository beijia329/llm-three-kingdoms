# ADR-0004 多级容错与兜底（游戏必须跑到结束）

- **状态**：Accepted（已落地，architecture.md 十三 + players/llm/llm_player.py）
- **日期**：2026-06-24（记录于 Phase 5→6 收口）
- **相关**：architecture.md 十三（容错与兜底机制）、llm-integration.md 3.6/3.7、players/llm/llm_player.py

---

## 背景（Context）

LLM 可能：格式错、API 宕机、网络抖动、429 限流、密钥失效。游戏的核心特要求是——**任何组件失败都不能导致整个游戏崩溃**，且 12 方对战少一方会严重破坏平衡。架构必须优雅处理所有这些异常（architecture.md 13.1）。

---

## 决策（Decision）

**三层容错体系**：

| 层 | 容错手段 |
|----|---------|
| 游戏层（GameEngine） | 状态合法性校验、异常隔离、最大回合数 `MAX_TURNS=192` 强制结束 |
| 玩家层（Player） | 超时保护、重试、降级、空命令兜底 |
| LLM 层（LLMClient） | 网络重试（指数退避）、超时、429 处理 |

**三级降级**（`players/llm/llm_player.py` 的 `get_commands`）：

```
L0 正常输出
  ↓ 解析失败
L1 重试（最多 2 次，指数退避 1s→2s，把错误回灌 LLM）
  ↓ 重试仍失败
L2 空命令（本回合跳过）
  ↓ 连续失败达 consecutive_fail_limit = 3
L3 降级为随机 AI（保底策略，全程随机）
```

- 连续 5 回合 API 调用失败 → 标记该玩家"离线"，全程随机 AI。
- **降级选择"随机 AI"而非"直接踢出"**（architecture.md 13.5 论证）：保平衡（少一方破坏三方以上对战）、保节奏（挂机无聊）、评测可比（崩溃本身是评测结果）、数据完整（随机 AI 产出完整对局）。
- 随机 AI 复用 `GameRandom`（与 ADR-0002 协调），策略合法（发展/征兵），作为"LLM 基准线"。
- **异常隔离**：一个玩家出错/超时不影响其他玩家（`ThreadPoolExecutor` + per-faction 超时，llm-integration.md 7.1）。
- 最坏情况：所有玩家降级为随机 AI，游戏仍能正常结束（192 回合上限保证不无限循环）。

---

## 后果（Consequences）

**正面**
- 无论 LLM 多低能都能跑到结束；评测报告可标注"哪些模型出现过异常"。
- 随机 AI 提供可量化的 baseline（衡量 LLM 比随机强多少）。

**负面**
- 降级后该方强度骤降，可能让对局短期失衡（但优于缺一方）。
- 随机 AI 也消耗 RNG 状态，需与确定性 ADR 协调（已实现：`LLMPlayer(rng=...)`）。
- 日志必须把降级事件标红（WARNING）便于排查——若未落实则降级"静默发生"，难定位。

---

## 备选方案（Alternatives Considered）

| 方案 | 结论 |
|------|------|
| 失败即判负/踢出异常玩家 | 破坏平衡与评测公平性，否决 |
| 纯空命令挂机 | 游戏变无聊、数据不完整，否决 |
| 无限重试 | 可能卡死整局，否决（仅 L1 有限重试） |
