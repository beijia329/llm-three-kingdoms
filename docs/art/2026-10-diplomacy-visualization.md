## 1. 做了什么

`DiplomacyPanel` 的「关系」tab 原来只有**列表** + 一个**没有行列标题**的 24 格色块网格。
README 把「外交博弈：信使系统、正式盟约、流言策反、背盟欺诈」列为头部特性，
但这套数据在界面上基本看不见。本轮补两个视图（新文件 `web/src/components/DiplomacyGraph.tsx`）：

| 视图 | 是什么 | 解决什么 |
|---|---|---|
| **`RelationGraph`** 环形关系图 | 12 方按环布点，**非中立关系**画连线；颜色 = 战/盟/和；粗细与深浅 = 关系强度；**点势力节点 = 只看它的关系**（再点取消） | 「一眼看出谁和谁在打」的网络形态；聚焦后解决边多时的"毛线球" |
| **`RelationMatrix`** 关系矩阵 | **12×12 完整矩阵**，行列各挂势力单字徽标，格内文字 = 该对关系，浅色空格 = 中立；悬停给「双方名 + 状态 + 信任度」 | **全部 66 对**都能定位。原实现只有 24 个无标色块，看到"战"也不知道是谁跟谁 |

配套改动：
- 观战模式（无人类势力）下的「当前战况摘要」列表：原来取 `faction_relations.slice(0, 12)`，
  而关系数组前 12 条**全是「汉室↔X」**，看不出战局 → 改为按关系强度排序的**真实战况**（`topRelations`）。
- 状态配色/单字标签抽到 `DiplomacyGraph.tsx` 单一事实源，面板不再各写一份。

### 技术选型
纯 **SVG + React state**，不引入图形库、不改 `GameMap`。放进 300px 宽的面板内（矩阵 260px、环图 276px）。
理由见 §4「为什么不做在地图上」。

## 2. 三个实测坑（都已处理，勿踩回去）

| # | 坑 | 实测证据 | 处理 |
|---|---|---|---|
| a | **`neutral` 会作为关系的一方出现** | 打中立城时会生成 `caocao↔neutral` 这类记录。实测 turn 4 起节点数 = **13** = 12 真实势力 + `neutral`；turn 20 时有 4 条含 `neutral` 的对 | 按 id 排除。`neutral` 不是势力（无君主 / 无 LLM / 无领地），画成第 13 个节点是错的。`FACTION_COLORS.neutral='#666666'` 存在，所以它会**安静地**渲染成一个灰节点——典型能瞒过 review 的缺陷 |
| b | **`neutral` 既是势力 id 又是状态值** | `status ∈ {war, neutral, alliance, truce}`，同时 `faction_a/b` 也可能是 `'neutral'` | 两个命名空间分开命名：`NON_FACTION_ID`（id）vs `status`（状态），禁止混用 |
| c | **开局 66 对全 `neutral`、trust 全 50** | 实测 **turn 1：66 条全部 neutral** | 中立关系**默认不画**（只画 战/盟/和）。若无条件画 66 条灰线，第一眼是一坨一模一样的线，比列表还难读。空状态给出明确文案：「开局：12 方互不相犯（66 对关系全部中立）」 |

> 关系强度定义（写进图例，避免"线粗是什么意思"无人知道）：
> **战争：越不信任越强；同盟/停战：越信任越强。**

## 4. 🔴 重要发现：同盟为何在这批实测里为零 —— **口径问题，不是阈值问题**

> ⚠️ **本节已于 2026-10-03 被 team-lead 更正。** 初版结论「CLI 模式下同盟永不发生、
> 根因是 `> 0.3` 阈值、README 的『正式盟约』是空承诺」**被实测推翻**，
> 错误部分见 §4.4「原结论错在哪」。更正依据：`tests/balance/exp19_diplomacy_reachability.py`。

**实测（初版）**：`seed=42` 跑满 48 回合，`alliance` / `truce` **恒为 0**；随后**再扫 40 个 seed（1–40，每个 48 回合），同样全部为 0**。合计 **41 局、约 1968 回合，零同盟、零停战**。

### 4.1 机制描述（这部分正确，保留）

1. `players/cli_player.py:93` —— CLI 玩家**只在收到结盟提议时**才会回发 `ProposeAllianceCommand`；
   而发起方唯一的动作是发一条**含"结盟"字样的外交消息**（`:135`），靠接收方 `receive_message` 的关键字匹配（`:75-77`）转成"待接受提议"。
2. 接受门槛是 **`self._diplomacy > 0.3`（严格大于）**（`:93`）。
   而 `game/personality.py:46-59` 里 12 方的 diplomacy 为：
   **`> 0.3` 只有 3 方（han 0.5、liubei 0.5、liubiao 0.4）**；
   **`= 0.3` 的 3 方（yuanshao / liuyan / yuanshu）不满足严格大于**；其余 6 方 ≤ 0.2。

### 4.2 真正的根因：**这条链路依赖 `receive_message` 回调，而多数路径不投递它**

`receive_message`（把外交消息投递给玩家对象）**全仓只有 1 个生产调用点**：

| 路径 | 是否投递 `receive_message` |
|---|---|
| `main.py` CLI `--mode ai-vs-ai` | ✅ 投递（`main.py:134-136`） |
| `api/game_manager.py`（Web 围观台） | ❌ **不投递** |
| `tests/balance/pacing_lib.py`（平衡实验台） | ❌ **不投递** |

`CLIPlayer` **只能**靠该回调得知「有人提议结盟」。故在**不投递**的路径上，
`_pending_alliance` 永远为 `None`，`ProposeAllianceCommand` **结构性不可能被发出** ——
41 局零同盟正是这个原因，与阈值无关。

### 4.3 两变体对照实测（`exp19`，5 局 × 48 回合，`PYTHONHASHSEED=0`）

```
变体 A：不投递（= tests/balance 现行口径）
  总回合 240｜外交消息 560 条｜结盟提议发出 0 次
  [阳性对照] 战争对 175 ｜ 停战 0 ｜ 同盟 0

变体 B：投递（= main.py 真实 CLI 路径）
  总回合 240｜外交消息 521 条｜结盟提议发出 92 次
  [阳性对照] 战争对 175 ｜ 停战 0 ｜ 同盟 47 对
```

阳性对照双变体均命中（战争对 175/175），故 0 与 47 都是真实差异，不是探针失效。

补充：同盟**不是瞬态**。`seed=42` 同盟峰值 7、**终局仍为 7**，48 回合中有 45 回合存在同盟
（seed=43：3/3，45 回合；seed=44：峰值 5、终局 3，47 回合）。所以「只取终局快照」
也**不会**得到 0 —— 零同盟无法用采样方式解释，只能是没投递。

### 4.4 原结论错在哪（如实记录）

| 初版结论 | 实测 |
|---|---|
| 「CLI 模式下同盟永不发生」 | ❌ 错。**实验台口径**下永不发生；`main.py` CLI 真实路径下正常发生（5 局 47 对） |
| 「根因是 `> 0.3` 严格大于，3 方被永久排除」 | ❌ 错。该门槛**只限制谁有资格回应，不限制谁先提议**——0.3 方先发消息、由 >0.3 方回应即可成盟。实测同盟对里**含** `('han','yuanshao')`、`('han','yuanshu')`、`('liubei','liuyan')` 等，正是那 3 个"被排除"的势力 |
| 「可结盟对上限 3 对」 | ❌ 错。实测 5 局出现 **47 对** |
| 「README 的『正式盟约』是空承诺」 | ⚠️ 需分开说，见 §4.5 |

错因复盘：把「在某个特定驱动口径下观测为 0」直接推广成了「在产品里不可能」，
且**未先确认被测路径与产品路径是否等价**。这与本项目反复记录的「假零命中」同族。

### 4.5 更正后的准确表述（写 v4.1.0 更新日志请用这版）

- ✅ **同盟机制本身可用**：`main.py` CLI 路径下每局都会形成同盟（64 回合内峰值 3–7 对），
  README 的「正式盟约」**不是空承诺**。
- 🔴 **但 `tests/balance/` 的平衡实验台与产品路径不等价**：实验台不投递 `receive_message`，
  于是**此前全部平衡实验都在一个「启发式玩家不可能结盟」的世界里运行**
  （外交消息照发 560 条，结盟提议 0 次，同盟 0、停战 0）。
  凡涉及外交的平衡结论，口径都需重新定义。
- 🔴 **Web 的规则-AI 回退模式同样无法结盟**（`api/game_manager.py` 不投递）。
  Web 的 **LLM 模式不受影响**——`LLMPlayer` 走 `observation.received_messages`
  （`prompt_builder.py:304`），不依赖该回调。
- 🔴 **停战（truce）是真瓶颈**：两变体下均为 **0 对**，即使真实 CLI 路径也从未发生。
  这是独立遗留项，与本节口径问题无关，值得单独追。
- 待办：`cli_player.py:93` 的严格 `>` 是否放宽到 `>=`，属**数值调优**范畴，
  与本节的「口径不等价」是两件事，不要混为一谈。

## 5. 本次不做 / 已知限制
- **背盟高亮：不做。** 后端**没有背盟信号**——`game/` 里的"违背"均指**违背君主本性的人设代价**，与外交无关（全仓搜 `背盟/betray` 只命中文档与 README）。它需要先加 `EventBus` 事件，而那要动 `game/engine.py`（本轮被 engineering-lead 占用）。
- **不做在地图上。** 备选方案是「势力间箭头画在势力领地之间」。否决理由：实测第 20 回合已有 **20 条真实交战**、第 48 回合 **40 条**（见下表），画到地图上必然成毛线球，还会与 C2 战斗叠层（箭头 + 结果环）抢注意力；而面板里的矩阵/聚焦图能容纳全部 66 对。**代价**：外交视图需要点开「外交」tab 才看得到，不是"一抬眼就在"。
- 矩阵在面板里位于下方，300px 宽 × 878px 高下需要滚动一次才能看全（截图已按滚动前后各出一张）。
- 聚焦是**单选**（一次只看一个势力），没有多选/对比。

> 附：真实交战条数随回合增长（seed=42，实测）
> turn 1 → 0 ｜ turn 8 → 7 ｜ turn 20 → 24（真实势力间 20）｜ turn 25 → 26 ｜ turn 48 → 40
