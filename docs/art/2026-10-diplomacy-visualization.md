---

## 1. 做了什么

`DiplomacyPanel` 的「关系」tab 原来只有**列表** + 一个**没有行列标题**的 24 格色块网格。
README 把「外交博弈：信使系统、正式盟约、流言策反、背盟欺诈」列为头部特性，
但这套数据在界面上基本看不见。本轮补两个视图（新文件 `web/src/components/DiplomacyGraph.tsx`）：

| 视图 | 是什么 | 解决什么 |
|---|---|---|
| **`RelationGraph`** 环形关系图 | 12 方按环布点，**非中立关系**画连线；颜色 = 战/盟/和；粗细与深浅 = 关系强度；**点势力节点 = 只看它的关系**（再点取消） | 「一眼看出谁和谁在打」的网络形态；聚焦后解决边多时的"毛线球" |
| **`RelationMatrix`** 关系矩阵 | **12×12 完整矩阵**，行列各挂势力单字徽标，格内文字 = 该对关系，浅色空格 = 中立；悬停给「双方名 + 状态 + 信任度」 | **全部 66 对**都能定位。原实现只有 24 个无标色块，看到"战"也不知道是谁跟谁 |

配套改动：
- 观战模式（无人类势力）下的「当前战况摘要」列表：原来取 `faction_relations.slice(0, 12)`，
  而关系数组前 12 条**全是「汉室↔X」**，看不出战局 → 改为按关系强度排序的**真实战况**（`topRelations`）。
- 状态配色/单字标签抽到 `DiplomacyGraph.tsx` 单一事实源，面板不再各写一份。

### 技术选型
纯 **SVG + React state**，不引入图形库、不改 `GameMap`。放进 300px 宽的面板内（矩阵 260px、环图 276px）。
理由见 §4「为什么不做在地图上」。

## 2. 三个实测坑（都已处理，勿踩回去）

| # | 坑 | 实测证据 | 处理 |
|---|---|---|---|
| a | **`neutral` 会作为关系的一方出现** | 打中立城时会生成 `caocao↔neutral` 这类记录。实测 turn 4 起节点数 = **13** = 12 真实势力 + `neutral`；turn 20 时有 4 条含 `neutral` 的对 | 按 id 排除。`neutral` 不是势力（无君主 / 无 LLM / 无领地），画成第 13 个节点是错的。`FACTION_COLORS.neutral='#666666'` 存在，所以它会**安静地**渲染成一个灰节点——典型能瞒过 review 的缺陷 |
| b | **`neutral` 既是势力 id 又是状态值** | `status ∈ {war, neutral, alliance, truce}`，同时 `faction_a/b` 也可能是 `'neutral'` | 两个命名空间分开命名：`NON_FACTION_ID`（id）vs `status`（状态），禁止混用 |
| c | **开局 66 对全 `neutral`、trust 全 50** | 实测 **turn 1：66 条全部 neutral** | 中立关系**默认不画**（只画 战/盟/和）。若无条件画 66 条灰线，第一眼是一坨一模一样的线，比列表还难读。空状态给出明确文案：「开局：12 方互不相犯（66 对关系全部中立）」 |

> 关系强度定义（写进图例，避免"线粗是什么意思"无人知道）：
> **战争：越不信任越强；同盟/停战：越信任越强。**

### 诚实判定
- **「谁和谁在打」= 读得出。** 两条路径都成立：
  - 第 8 回合（7 条）在**环形图上直接可读**——能逐条追出 汉↔曹、黄↔曹、董↔公、董↔备、备↔公、备↔焉、孙↔公。
  - 第 20 回合（20 条）图上已接近"毛线球"、**单看环图读不出全部**；此时靠**聚焦**（点曹操 → 只剩它 6 条，其余淡出）与**矩阵**（20 个"战"格按行列可逐一定位）仍完全可读。
- **「谁和谁结盟」= 读不出，因为数据里没有。** 见 §4。这是**数据缺失**，不是视图缺陷——视图中「盟/和」的渲染路径已实现，但**无真实数据可验证**（我没有伪造数据）。

## 4. 🔴 重要发现：CLI 模式下「同盟 / 停战」实际上永远不会发生

**实测**：`seed=42` 跑满 48 回合，`alliance` / `truce` **恒为 0**；随后**再扫 40 个 seed（1–40，每个 48 回合），同样全部为 0**。合计 **41 局、约 1968 回合，零同盟、零停战**。

**根因（读代码 + 实测对照）**：
1. `players/cli_player.py:93` —— CLI 玩家**只在收到结盟提议时**才会回发 `ProposeAllianceCommand`；
   而发起方唯一的动作是发一条**含"结盟"字样的外交消息**（`:135`），靠接收方 `receive_message` 的关键字匹配（`:75-77`）转成"待接受提议"。
2. 接受门槛是 **`self._diplomacy > 0.3`（严格大于）**（`:93`）。
   而 `game/personality.py` 里 12 方的 diplomacy 为：
   **`> 0.3` 只有 3 方（han 0.5、liubei 0.5、liubiao 0.4）**；
   **`= 0.3` 的 3 方（yuanshao / liuyan / yuanshu）被这个严格大于号永久排除**，其余 6 方 ≤ 0.2。
3. 于是"发起方发消息 → 恰好选中这 3 方之一 → 该方信任够 → 回发提议"这条链，41 局里一次都没走通。

**要有人管的话**（不在本轮范围，且我**未改任何后端**）：
- `game/personality.py` 的数值与 `cli_player.py:93` 的严格 `>` 是否应该放宽到 `>=`；
- 或让 CLI 玩家**主动**发起结盟（目前它只会"响应"）。
在此之前，README 的「**正式盟约**」在默认（CLI）模式下是**空承诺**——这条建议写进 v4.1.0 更新日志的措辞里。

## 5. 本次不做 / 已知限制
- **背盟高亮：不做。** 后端**没有背盟信号**——`game/` 里的"违背"均指**违背君主本性的人设代价**，与外交无关（全仓搜 `背盟/betray` 只命中文档与 README）。它需要先加 `EventBus` 事件，而那要动 `game/engine.py`（本轮被 engineering-lead 占用）。
- **不做在地图上。** 备选方案是「势力间箭头画在势力领地之间」。否决理由：实测第 20 回合已有 **20 条真实交战**、第 48 回合 **40 条**（见下表），画到地图上必然成毛线球，还会与 C2 战斗叠层（箭头 + 结果环）抢注意力；而面板里的矩阵/聚焦图能容纳全部 66 对。**代价**：外交视图需要点开「外交」tab 才看得到，不是"一抬眼就在"。
- 矩阵在面板里位于下方，300px 宽 × 878px 高下需要滚动一次才能看全（截图已按滚动前后各出一张）。
- 聚焦是**单选**（一次只看一个势力），没有多选/对比。

> 附：真实交战条数随回合增长（seed=42，实测）
> turn 1 → 0 ｜ turn 8 → 7 ｜ turn 20 → 24（真实势力间 20）｜ turn 25 → 26 ｜ turn 48 → 40

```bash
cd web && npx tsc --noEmit && npx vite build        # 后端同源托管 dist
GAME_SEED=42 GAME_MAX_TURNS=48 GAME_MODE=standard \
  SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy \
  python3 -m uvicorn api.server:app --host 127.0.0.1 --port 8016
cd web && node verify-diplomacy.mjs http://127.0.0.1:8016 /tmp/dip 20 曹操
```
