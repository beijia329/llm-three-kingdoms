## 0. 结论速览

「太卡通」**不是"配色丑"**，是**五个现代 UI 范式**在同时发力——圆角、高饱和 Material 色、纯色平涂无材质、毛玻璃、现代无衬线字体。逐条都能定位到具体代码：

| # | 卡通来源 | 具体证据（读代码） |
|---|---|---|
| 1 | **圆角过大且不统一** | 全站 `borderRadius` 出现 **11 种值**：2/3/4/5/6/7/8/10/12/16/20（`Panel.tsx`/`CityCard.tsx`/`LlmSetupBar.tsx`） |
| 2 | **高饱和现代色** | 主色 `#d4a84b`（电竞金，硬编码 **60 处 / 14 文件**）；`blue #64a0d2`、`purple #9370DB`、`green #5ab464` —— **全是 Material Design 标准色** |
| 3 | **纯色平涂，无材质** | 面板 = `rgba(18,18,34,0.88)` 纯色块，无纸纹/绢纹/木纹 |
| 4 | **毛玻璃 + 霓虹光** | `backdropFilter:'blur(12px)'`（TopBar/Panel）、`boxShadow:'0 0 12px gold'` 霓虹辉光 |
| 5 | **现代无衬线字体** | 全站 `Noto Sans SC`，标题也用它（汉风标题需**宋体/楷体**） |
| 6 | **无印章 / 无留白节奏** | 无钤印、无题跋式留白，元素等距贴边 |
| 7 | **emoji 当语义图标** | `🏯`/`🏰`/`🏆`/`⚔`/`🤝`（`GameMap.tsx:315`、`Panel.tsx:372`、`BattleOverlay.tsx:346`、结束界面） |
| 8 | **关键模块比例失衡** | 外交矩阵挤在 `PANEL_W=300`、结算卡固定 `380px`（`theme/index.ts:178`、`GameOverOverlay.tsx:92`）——**把「外交博弈」卖点做没了** |

下面的 §2 给出**一套可替换的 token 表**（§3），让「古韵」从形容词变成可 `diff` 的数值。

> **一句话方向**：把「蓝紫黑 + 电竞金 + 毛玻璃 + 大圆角」换成「**墨青绢本 + 朱砂赭金 + 纸纹 + 直角小半径**」。

## 1. 现状诊断（逐条给证据与定位）

### 1.1 底色是「蓝紫黑」，不是「墨」
- `bg: '#1a1a2e'`、`panelBg: 'rgba(18,18,34,0.88)'` —— 带明显**蓝紫**色偏（B 通道 > R/G），是 Material 深色主题的典型底。
- 中国水墨/绢本的"黑"应是**墨青（`#16222B`）或墨褐**，带一点点青/褐，不带紫。**紫色调 = 赛博感/现代感**，是"不古韵"的第一来源。

### 1.2 主色是「电竞金」，不是「古铜金」
- `gold: '#d4a84b'` —— 高饱和、偏橙的金属金，非常"游戏 UI"。
- 且它**以纯色平涂硬编码 60 次**（`Panel.tsx` 22 次、`DiplomacyPanel.tsx` 8 次、`LlmSetupBar.tsx` 7 次…），既没有材质层次，也无法统一调。
- 古韵金应是**古铜/赭金 `#C8A85A`**（降饱和、偏土黄），并与**朱砂 `#9D2933`** 搭配（朱砂+金是古书画/印章的经典组合）。

### 1.3 强调色是 Material 三件套
`blue '#64a0d2'`、`purple '#9370DB'`、`green '#5ab464'` —— 与 Material Design 官方色板几乎逐位对应。**这三个色是"卡通/现代"被一眼识别的关键**，需替换为中国传统色（天青 / 藕紫 / 竹青），并把饱和降下来。

### 1.4 圆角与玻璃拟态
- 圆角 8/10/12/16/20px 的卡片、`borderRadius: 999` 的胶囊按钮 —— 现代 rounded。
- `backdropFilter: blur(12px)` + 半透明底 —— **毛玻璃（iOS/现代 Web）**。

### 1.5 字体是现代无衬线，宋体只占 3 处
- 仅 `Noto Sans SC` 一套（`web/index.html:31`、`theme/index.ts:187`）+ Font Awesome CDN。
- `theme/index.ts:188` 的 `font-serif`（`"Songti SC","STSong","SimSun",serif`）**全站只被 3 处引用**：顶栏标题、城池卡城名、帮助面板标题。右侧面板的**势力名/数值/战报/外交/决策/结算几乎全为无衬线** → 读感偏「现代数据看板」。
- **要古韵，字体层面几乎是"从零做"**（QA 基线 M1 原话）。
- 无任何纸/绢/木材质；边框仅 `1px solid rgba(255,255,255,0.08)`。
- 地图已是「深色海 + 羊皮纸陆」，**UI 与地图风格割裂**（一个是羊皮纸古地图，一个是深色数据看板）。

### 1.6 emoji 当语义图标用（与古韵直接相斥）
- `🏯` 城名前缀（`GameMap.tsx:315`）、`⚔` 战斗标签（`BattleOverlay.tsx:346`）、`🏰` 称王事件（`Panel.tsx:372`）、`🏆`/`🤝` 结束界面。
- emoji 是**跨平台渲染不一致的彩色拟物**，与「墨/绢/印」的古韵语境**直接冲突**（QA 基线 M2）。

### 1.7 关键模块比例失衡（把卖点做没了）
- **外交**（QA 基线 M4）：环形关系图 + 12×12 关系矩阵塞进固定 `PANEL_W=300`（`theme/index.ts:178`），矩阵格与图例仅 ~10px、需滚动、底部截断 → **「外交博弈」这个差异化卖点在界面上看不清**。
- **终局**（QA 基线 M5）：结算卡固定 `380px` 宽、headline 24px（`GameOverOverlay.tsx:92`），在 1920 宽屏上只占约 1/5，**胜者不够压场**。

## 2. 古韵方向

### 2.1 两条方向路线（**请用户拍板选一**）

| | **方向甲 · 绢本墨色（推荐）** | **方向乙 · 宣纸浅色** |
|---|---|---|
| 配色基调 | 深墨青/绢底 + 朱砂/赭金 点缀 | 米黄宣纸底 + 墨字 + 朱砂印 |
| 观感 | 夜观舆图 / 元代文人画 | 白天摊开的古地图 / 宋版书 |
| 与地图协调 | ✅ 与深色海、羊皮纸陆**同属暗色**，统一 | ⚠️ UI 亮、地图暗，对比强，需重调地图描边 |
| 改动量 | **小**（底色微调 + 强调色替换 + 圆角收小） | **大**（全局反色，卡片/阴影/文字全改） |
| 风险 | 低 | 中高（对比度/可读性要重验） |

> **本规范默认按「方向甲」给 token**；方向乙的关键值在 §3.4 附表。

### 2.2 配色（中国传统色，含 hex，均已联网核验色名）

选色依据：搜索到的中国传统色色谱（ysdaima / ip138 / tie.pub 三源交叉）。**只取色名与色值（公共色彩知识），不涉及任何素材版权**。

| 古韵角色 | 色名 | hex | 用途 |
|---|---|---|---|
| 底（墨） | 墨青 / 青山黛 | **`#16222B`** | 应用最底、地图外框、深色面板 |
| 次级底 | 黛青（提亮） | **`#1F2E38`** | 悬浮层、次级面板、输入框 |
| 纸（绢本） | 绢本 | **`#E8DCC5`** / `#EFE6D2` | 浅色块、印章底、进度槽 |
| 墨字 | 墨 | **`#2C2C2C`** / `#3A332B` | 文字、描边、线条 |
| 米白字 | 缟 / 茶白 | **`#EDE6D6`** | 深底上的主文字 |
| 朱砂（重音） | 朱砂 / 胭脂 | **`#9D2933`** | 印章、危险、交战、删除 |
| 赭石（次重音） | 赭石 | **`#9C5B2D`** | 标签、木牌、次强调 |
| 古金 | 秋香 / 赭金 | **`#C8A85A`** | 主强调、边框、选中（替代 `#d4a84b`） |
| 天青 | 天青 | **`#4A6FA5`** | 信息、政治、友方 |
| 竹青 | 竹青 | **`#5B7A4E`** | 成功、守成、忠诚 |
| 藕紫 | 藕荷 / 丁香 | **`#6B5A82`** | 辅助、第三序列 |

> 用法约束：**朱砂只在"最重的动作/状态"上出现**（印章、危险、交战），面积 ≤ 5% 屏幕；**金只做线与描边**，不做大色块平涂——这直接消解「电竞金平涂」的现代感。

### 2.3 材质 / 纹理

| 部位 | 做法 | 参数 |
|---|---|---|
| 面板底 | **绢纹/纸纹** seamless tile 叠加 | `opacity 0.04–0.06`、`mix-blend-mode: multiply`（深底）/ `overlay`（浅底）；tile 256² WEBP ≈ 20–60K |
| 地图外框 | 已有 `web/src/assets/ui/panel-frame.svg`（Kenney CC0，九宫格） | 色改 `#5a4a24 / #f0e2b4 / #b9974a`（已做），扩展到全局面板 |
| 分隔线 | **双线**（主 1px + 副 2px，中间留 2px） | 主 `#5A4A38`、副 `#8A7A60` @0.5；替代 `1px solid rgba(255,255,255,0.08)` |
| 阴影 | **去掉霓虹辉光**，改**低扩散投影** | `0 2px 8px rgba(0,0,0,0.35)`；选中态才用 1px 古金描边 |
| 印章 | 标题/势力名旁**朱砂方印**（纯 CSS：`#9D2933` 底 + 米白字 + 1px 描边） | 16–20px 方、圆角 2px、`rotate(-3deg)` |

**纹理来源（许可）**：ambientCG（**CC0**，无需署名）、Poly Haven（**CC0**）。二选一即可，单张 256² → 首屏增量 < 60K。

### 2.4 字体（含体积代价）

> 本项目**已有实测账**（见 `2026-10-art-and-ui-audit.md` 附三/附四），此处直接沿用结论，不重复试错。

| 用途 | 字体 | 许可 | 体积代价 / 结论 |
|---|---|---|---|
| **标题 / 回合数 / 州名** | **系统衬线栈** `"Songti SC","STSong","SimSun","Noto Serif SC",serif` | 系统自带 | **零请求 / 零延迟**（现状已用，保留） |
| 正文 / 面板 / 数据 | `Noto Sans SC` | OFL 1.1 | 现状保留（可读性优先） |
| 事件流 / 决策正文 | **霞鹜文楷 LXGW WenKai** | SIL OFL 1.1 | **已局部接入**（按需分片，首屏 FCP 无退化，实测 LAN 508→496ms） |
| （可选升级）真·宋体标题 | 思源宋体 Source Han Serif SC | SIL OFL 1.1 | 单字重 8–13MB → **必须子集化**；作为"若要求更极致古韵"的**备选**，非本轮必做 |

**不建议**：全局替换中文 Web 字体（霞鹜文楷全局净增 71K、Fast3G FCP +360ms，且无 Bold 字重）。**维持"系统衬线栈（零成本）+ 局部霞鹜文楷（已在用）"**。

### 2.5 边框 / 分隔 / 留白与层次

- **边框**：从 `1px solid rgba(255,255,255,0.08)`（现代细白框）→ **淡金褐描边 `rgba(200,168,90,0.18)`** 或**九宫格木框**（Kenney）。
- **分隔**：用「双线」或「回纹/云纹」SVG 分隔（game-icons 或自绘），替代纯 1px 线。
- **留白**：启用已有 `SPACE` 刻度（4/8/12/16/24）；面板内边距统一 **16px**、卡片间距 **12px**、标题下留白 **8px**。目标：**密集区 60% / 呼吸区 40%**（学 EU4 的信息密度比）。
- **层次**：靠**明度**分层（墨青底 → 黛青卡片 → 绢本高亮），不靠花哨描边。

### 4.1 两处比例失衡的修法（M4 / M5）

> **📌 2026-10-04 修正（据 QA 实测，`docs/qa/2026-10-04-M2-M4-证据.md` §2）**：我原稿把 M4 判成"面板太窄、矩阵被挤"，**这个前提是错的**。实测：矩阵 **260px 宽 < 可用 276px → 横向放得下、不溢出**；真问题是**纵向堆叠**（环形图 + 图例 + 战况摘要 8 行 + 矩阵 = **scrollH 1141px > clientH 984px**，把矩阵挤出视口 **157px**）。**因此"把矩阵格加大"会加剧溢出、"单纯拓宽面板"也不解**——正确方向是**改版式**。下表已按实测重写。

| 问题 | 现状（实测） | 规范 |
|---|---|---|
| **M4 外交视图纵向溢出** | 面板 `PANEL_W=300`（可用 ~276px）；矩阵单元格 **20×20px**、字号 10px、矩阵 **260×260px**；`scrollH 1141 > clientH 984`，矩阵被截 **157px** | **①【推荐】关系视图加「环形图 / 关系矩阵」二选一开关**（segmented）：一次只渲染一个，各得满高（矩阵 260px 轻松放下）。成本小、不动面板宽度，符合"渐进披露"。**②【备选】面板拓宽到 420–480px + 「图｜矩阵」左右分栏**（需同时改纵向布局，否则仍溢出）。**③ 摘要折叠**：把「当前战况摘要」(8 行)默认折叠。**④ 不要做**：加大矩阵单元格（会加剧纵向溢出）、仅加宽面板（不解） |
| **M5 结算卡太小** | 固定 `380px` 宽、headline 24px，1920 屏上仅占 1/5 | 结算卡宽 = `clamp(380px, 32vw, 640px)`；胜者名 headline **32–40px**（用 `--font-serif`）；加**朱砂印章**与主次分层。**文案真源=后端 `format_end_copy`，前端 verbatim 渲染**（已拍板，见下方注） |

## 7. 改动量最大的三处（供主理人排期）

1. **`Panel.tsx` —— 22 处硬编码 `#d4a84b` + 多套 `styles` 的圆角/间距**。右栏是视觉重心，也是 token 泄漏最严重处；不改这里，古韵只做了一半。
2. **全局 `UI_COLORS` 换血 + 60 处硬编码金清理**（14 个文件）。这是"一调就全错"的根因，必须一次性走 token。
3. **字体层级重做**（标题从 `Noto Sans SC` 换回 `--font-serif` 衬线栈，正文/事件流分层）——**零体积成本**，却是"汉风层级"最直接的一招。

> 性价比排序：**先做 §3 token 替换（含清理硬编码）→ 再做 §7.3 字体分层 → 最后才碰材质/边框**。前两步几乎零风险、零体积，即可消除 80% 的"卡通感"。
>
> **另有两条"零成本先手"建议放第一批**：**清 emoji（§1.6 / §4 图标行）** 与 **外交矩阵/结算卡的比例修正（§4.1）**——改动小，但直接命中玩家"不够古韵 / 卖点看不清"两条反馈。
