## 0. 结论速览

玩家的两条抱怨里，「棋局混乱」这一条**不是审美问题，是信息层级问题**。当前地图上同时只有 4 个视觉变量在起作用（羊皮纸底色 / 势力色块 / 两条几乎同粗的线 / 城点），而其中**最关键的两个维度——「谁的地」和「地形」——都没有被编码**：

| 维度 | 现状 | 后果 |
|---|---|---|
| **格网** | `GameMap.tsx:183` 地块**只 `fill` 无 `stroke`** → 陆地是一整块连续色块 | **没有棋盘 = 不像战棋**；观众没有"格"的空间参照（QA 基线 H2） |
| 地形 | `parchmentTint()` 只给了 17 档极近的纸色（ΔE 极小），**山地/森林/河流在整图上几乎看不出** | 观众不知道「这仗为什么在这打」 |
| 势力归属 | alpha 0.42 平涂 + 无边界线 + 无归属标注 | 势力色像「水渍」，两邻国接壤处糊在一起 |
| 界线层级 | 势力界 3px、州郡界 1.2px，**两者都只是"线"，没有粗细/虚实/颜色的层级差** | 分不清哪条是国家界、哪条是行政区界 |
| 标记比例 | 城池 16–32px、军队 12–30px，**两者量级重叠**；图标尺寸由 zoom 连续插值，无档位 | 「比例没做好」的直接来源 |

**本规范要交付的，是一张"标尺表"（§4.7）+ 一套"线级/填色/标记"的编码规则（§4.1–§4.6）**，让实现者照着数值就能写，不再靠感觉调。

**一句话目标**：让观众**只看地图、不看侧栏文字**，3 秒内读出四件事——① 这块地是谁的；② 这是山还是河还是平原；③ 哪座城大、哪座城被围；④ 谁在打谁、从哪打向哪。

## 1. 调研依据（联网搜索结论，2026-10-04）

> 这一步是玩家的明确要求：「搜索战棋游戏一般要有哪些元素、用哪些素材」。以下为**学方法**（不抄资产）。

### 1.1 三国题材策略游戏的既有做法

| 作品 | 关键做法 | 对本项目的启示 |
|---|---|---|
| **《三国志14》** | 「涂色战争」：部队走过的每格自动染势力色，**地格 = 势力范围 = 补给线**；无国境线，靠**格子颜色密度**表达控制 | 领土填色必须**服务于"谁控制这块地"**，而不是装饰；填色要能透出下面的地形 |
| **《三国志14》势力色** | 曹魏 `#FFA400`、蜀汉 `#006400`、东吴 `#0000FF`、群雄 `#808080`——**高饱和、高明度、彼此色相远隔** | 现有 `FACTION_COLORS` 有多档低饱和「脏色」（董卓 `#1D1B24` 近黑、公孙瓒 `#6E8073` 灰绿），在羊皮纸上读不出——需要**明度下限**约束 |
| **《全面战争：三国》郡界** | 郡与郡之间用**按外交关系着色的界线**：白=中立、蓝=友好/盟、红=交战、黄=汉室；**郡界本身就是外交信息载体** | 势力界线的**颜色可以承载"关系"**：不仅区分你我，还能表达"在不在打仗"。这直接服务「谁在打谁」 |
| **《全面战争：三国》战场地图** | 己方绿、敌方红、未探索灰——**三色即三态** | 交战双方用固定语义色：攻方=势力色、守方=中性蓝，避免"两个势力色撞了认不出" |
| **《文明6》** | 迷雾三态：**可见 / 已探明(半雾，手绘地图感) / 未知(羊皮纸空白)**；陆地地形按类型着色（草原亮绿、平原黄绿、沙漠黄、山灰） | 本项目是**围观台、无迷雾**，但可借用其"**羊皮纸=未知/未纳入**"的语义；地形色要像"同色系但在明度上有台阶"，不要花斑 |

### 1.2 战棋（wargame）品类的通用元素与比例规范

搜索到两条**可直接落地的硬规则**：

1. **单位标记尺寸应按"地形格符号"的 60–75%**（HPS Simulations《Aide de Camp 2》官方案例：地形符号 40×40px → 单位符号 ≤30×30px；一格放 4 个单位时降到 ≤50%）。
   → 本项目：**城池标记 = "地形格"主角，军队标记 = 单位，军队应约为城池的 75–80%**（见 §4.7）。
2. **NATO 军标 / 兵棋 counter 的三层信息**：图标（兵种）+ 颜色条（敌我/类别）+ 数字（兵力/攻防）。
   → 本项目：图标=兵种/状态剪影，颜色=势力，数字=兵力。**这三层要有明确主次**，不能都做成同样醒目。

### 1.3 「信息层级」的现代战棋范例

- **《陷阵之志 Into the Breach》**：**一格只承载一种效果**；无法用一个画面说清时，就**盖一个图标**；开发组自述「一版接一版地加图标，一度变成 icon mess，最后靠**克制的编辑**（为清晰牺牲酷炫）才收敛」。
  → 启示：**图标不能靠叠加**，必须**分层级 + 分显示条件**（缩放到某档才显示、被选中才显示）。
- **颜色心理学**（同上文综述）：红/橙=危险与敌意、蓝=中性信息、绿=成功；**文字层级**：主标题 1.6–2.2× 正文、次标题 1.2–1.4×、正文行高 1.4–1.6×；**信息密度 60:40**（60% 密集区 + 40% 留白呼吸）。
  → 本项目右栏已固定 300px，**信息应下沉到地图**（CK3 的教训），地图本身要建立字号/线宽刻度。

### 1.4 中国古代舆图的符号传统（**本项目的"古地图风"应以此为纲**）

搜索到一份对历代古地图符号的系统梳理（《中地参》2024 表 1），**这是本项目地形/城池符号的直接设计依据**：

| 要素 | 古代制图法 | 本项目落地建议 |
|---|---|---|
| **山脉** | 宋代《九域守令图》《华夷图》用「**人字形**符号」；《广舆图》《皇舆全览图》沿用 | 山脉用 **∧（人字）符号 + 单侧阴影排线**，不用彩色贴图 |
| **河流** | 禹迹图/**双曲线**，**「上细下粗」**（上游细、下游粗）；湖泊用闭合曲线 | 河流**主干粗、支流细**，两侧加浅色描边 |
| **居民点/政区** | 方框=县、圆圈=乡（马王堆地形图）；**府=方、州=圆、县=长条**（明《广舆图》）；**都城=八角形内注名** | 城池用**形状+尺寸双编码**：等级越高形状越"重"、尺寸越大 |
| **城墙** | 清代全图「城池形象绘制城堞」 | 都城/重镇可加**城堞（垛口）剪影** |

> ⚠️ 版权红线：**不抄**光荣《三国志》的任何立绘/地图/UI/字体。上述仅为"制图方法"，均为公有领域的古法。

## 4. 元素清单（每条：现状 → 问题 → 规范）

> 约定：**所有尺寸标"屏幕 px"**（即在 CSS/画布像素下最终呈现的大小），除非注明"世界 px"（Pixi 世界坐标，会乘以 zoom）。这是本规范的硬约定——**比例混乱的根因，就是过去"世界 px"和"屏幕 px"混用**。

### 4.0 六角格网（棋盘结构）★★ 本轮最大缺口

> 对应 QA 基线 **H2**：*「整块陆地是一张连续填充的色块，看不到六角格网/格子边界（`GameMap.tsx` 地块仅 `fill` 无 `stroke`）。全图视角下版图是「一团团色斑」，没有战棋的「格子—单位—阵线」可读结构。」*
> **这是"作为战棋类游戏却不像战棋"的直接原因**——玩家要的"棋局"感，第一来源就是**看得见的格子**。

**现状**：`GameMap.tsx:183` `tilesGraphics.poly(points).fill(...)` —— **只有 `fill`，没有任何 `stroke`**。因此：
- 相邻**同势力**的格填色后连成一片 → 读不到格子；
- 势力色块边缘的六边形锯齿只在**领土边界**处偶然出现（那是势力界线的功劳，不是格网）。

**问题**：没有格网 = 没有棋盘 = 没有"落子/单位/阵线"的空间参照系。观众不知道一座城"影响几格"、一支军队"走了几格"、战线"推进了几格"。

**规范：双层格网**（两者叠加，各司其职）

| 层 | 做法 | 宽度（屏幕 px，恒定 ÷zoom） | 颜色 / alpha | 作用 |
|---|---|---|---|---|
| **A. 全局格网** | **每个陆地格** `poly().stroke(...)`，海格不描 | **0.6**（zoom<0.30）→ **0.8**（0.30–0.55）→ **1.0**（≥0.55） | `#5A4A38`；alpha **0.10 → 0.16 → 0.22** | 给整张陆地"经纬"感，让版图读成"格子集合" |
| **B. 领土格网** | 有主格额外描一圈 | **0.8** | **势力色 ×0.6**；alpha **0.35** | 让"同势力连成一片"里**仍看得见一格一格**（三国志14「涂色」的观感） |

**关键规则**
1. **格网必须画在「领土填色」之上、界线之下**（图层栈 ③.5）——否则 0.30 alpha 的填色会把下面的格线糊掉。
2. **格网线宽同样按 `k / zoom` 换算**（与 §4.2 一致），保证缩小后格线仍在屏幕上可见且不断线。
3. **LOD 门限**（避免 24000 格在全图时变噪点）：`zoom < 0.18` 时**只保留领土格网 B**（全局 A 关闭）；这样开局全图也能看出"哪几格是谁的"，不会糊。
4. **海格不描边**（海追求连续，陆地追求"格"）——陆海对比本身也是一层语义。
5. 性能：格网是**一个额外的 Pixi `Graphics`**，与地形同一次构建（`hex_map_version` 门控），**不逐格 Sprite**。

> **✅ 拍板结论（2026-10-04，team-lead）**：**采用双层（A+B）**，其中 **A 全局格网用极淡档作基底**（即上面表的低档值：0.6px / alpha 0.10 起）。「只做 B」的备选方案**不采纳**。
> 工程侧已排入 **D3 最前**（优先级 0），先于标尺表落地。

### 4.1 势力 / 领土

**现状**：`factionGraphics` 对每个有主的格画 `FACTION_COLORS[f]`、**alpha 0.42**、无描边；`getFactionAt()` 按城池 `cityRadius(level)` 半径（1–3 格）推断领土。

**问题**
- P1 平涂 0.42 把下面的地形（山脉/河流）**全盖住**——所以"看不出地形"和"填色"是**同一个 bug 的两面**。
- P2 相邻势力之间**没有分隔**，只有两块色相接，接壤处糊成一片。
- P3 部分势力色太暗（董卓 `#1D1B24`）或太灰（公孙瓒 `#6E8073`），叠上去像脏斑，且对底 `ΔE` 太小。
- P4 领土**没有归属文字/徽记**，色盲/灰度下完全认不出是谁。

**规范（数值）**

| 参数 | 现在 | 规范值 | 理由 |
|---|---|---|---|
| 领土填色 alpha | 0.42 | **0.30** | 让第 ③ 层地形透出来（学《三国志14》"涂色"仍要能读地形） |
| 领土色**明度下限** | 无 | 领土态 **L\* ≥ 34**（CIELAB） | 近黑势力（董卓）须改用中明度替身色，见下表 |
| 相邻势力可分辨 | 未定义 | 叠加在纸底 `#d9c9a3` 上后，**相邻对 ΔE ≥ 18**；**任一势力对底色 ΔE ≥ 12** | 沿用项目已有 CIELAB ΔE 方法（审计附二） |
| 领土边界 | 无 | 见 §4.2 势力界（3px 势力色） | 归属靠"线"而非"面" |
| 归属非颜色线索 | 无 | 每块**连通领土质心**放 1 个 `FACTION_GLYPH` 单字水印：字号 = `clamp(领土短边×0.18, 14, 40)`px，颜色 = 势力色×0.55、alpha 0.55，**置于填色层之上、标注层之下** | 色盲/灰度可认；呼应古图"政区文字标注" |

**近黑势力替身色建议**（保持原意象，只提明度）：

| 势力 | 现色 | 建议色 | 说明 |
|---|---|---|---|
| dongzhuo | `#1D1B24` | `#5A4A63` | 提亮为"暗紫褐"，仍有"篡逆/阴"的意象 |
| caocao | `#5E3828` | `#8A4B32` | 深褐 → 中褐（原色在纸底上发闷） |

> 其余势力色沿用（审计附二已做过 ΔE 优化），仅在改 alpha 后**重跑一次 ΔE 校验**即可。

### 4.2 界线层级（省界 / 州郡界 / 势力界）★ 本级是"治混乱"的核心

**现状**
- 势力界：`width 3`，色 = 势力色 `darken 0.55`，alpha 0.9（`GameMap.tsx:253`）。
- 州郡界：`width 1.2`，`INK_COLOR 0x4a3a28`，alpha 0.85（`GameMap.tsx:281`）。
- **问题**：两者只差粗细，**没有"虚实/颜色/层级"区分**；且都没有和"归属"绑定。全图缩放时两条线都细到看不清。

**规范：四级线标尺**（层级从低到高，越是"国界"越重）

| 级别 | 线 | 宽度(屏幕px) | 颜色 | 虚实 | alpha | 备注 |
|---|---|---|---|---|---|---|
| L1 | **省界/地形界**（若有 DataV 省界底图） | **1.0** | `#6B5A44` | 点线 `1,3` | 0.45 | 最淡，只在放大时可见 |
| L2 | **州郡界**（`province_id` 分组） | **1.8** | `#4A3A28`（INK） | 实线 | 0.72 | 行政区界 |
| L3 | **势力界** | **3.0** | **势力色 × 0.45**（暗化） | 实线 | 0.92 | 国界 |

| 根因 | 规范 |
|---|---|
| **① 线宽太细**（1–2px）→ 交叉处糊成一片 | 继承 §4.2：战斗箭头线宽按 `4 + 5×兵力占比` **屏幕 px 恒定**（÷zoom），起手就是 4px 级，不再被 zoom 压到 1px |

#### 4.8.1 🔴 TA 实施注意（已知坑）：`mask-image` 的 `url()` 必须加引号 / 别内联

> **2026-10-04 复验实锤**：emoji 已全部去掉（✅），但**替换图标在生产构建里渲染成`44×44`纯色方块**（❌），根因**不在资产**，在拼 CSS 的写法。

**机理**：生产构建下 Vite 把 `< 4KB` 的 SVG **内联成 data URI**，URI 中保留了 SVG 的属性引号（`xmlns='...'`）。若代码写**未加引号的 `url(${svg})`**，得到非法 CSS → 浏览器**丢弃 `mask-image`** → 只剩 `background-color` → **方块**。实测 `CSS.supports(...) = false`；`url("<uri>")` **加引号即修复**。

**代码实况（2026-10-04 grep，处于"部分已修"状态）**：

| 文件:行 | 写法 | 状态 |
|---|---|---|
| `EventTicker.tsx:31-32` | `url("${scrollQuill}")` | ✅ 已加引号 |
| `GameOverOverlay.tsx:59-60` | `url("${iconUrl}")` | ✅ 已加引号 |
| `CityMarker.tsx:48-49` | `url(${url})` | ❌ **未加引号** |
| `ArmyMarker.tsx:44-45` | `url(${url})` | ❌ **未加引号** |
| `map/BattleOverlay.tsx:17-18` | `url(${swordsIcon})` | ❌ **未加引号** |
| `CityCard.tsx:419` | `borderImage: url(${panelFrame}) 8 / 8px / 0 stretch` | ❌ **同机理**（borderImage 同样吃引号） |
| `ShortcutHelp.tsx:95` | 同上 | ❌ **同机理** |

**规范修复（三选一，建议 ①+③ 一起）**
1. **统一加引号**：所有 `url(${x})` → **`url("${x}")`**（含 `borderImage`）。
2. **关内联**：`vite.config.ts` 设 **`build.assetsInlineLimit: 0`** → SVG 输出为独立文件、URI 变成干净路径（`/assets/xxx.svg`），既规避引号问题，又利于缓存与 CSP。**体积影响可忽略**（图标均为 KB 级 SVG）。
3. **收敛成一个 helper**：把 3 处重复的 `maskStyle()`（CityMarker / ArmyMarker / BattleOverlay 各写了一份）**合并为单一 `maskUrl(url)` 工具函数**——避免"6 处各写一遍、修了 2 处漏 4 处"（本次正是这么漏的）。

**换图后的美术验收（我的责任）**
- 修复后需**回看三处特写**：结算四态图标、战斗标签 `crossed-swords`、地图城池/军队剪影是否**成形状**（不再是方块）。
- **辨识度**：game-icons 是**细节较多的剪影**，在 **11–24px** 下可能糊。若糊，按 §4.4 的"深描边"降复杂度——**优先换更简的变体**（如 `crown` 而非 `laurel-crown`），次选加 0.5px 深色外描边。
- ⚠️ **不要**为了"看起来清楚"而放大图标——尺寸必须服从 §4.7 标尺表（城池 14–26px、军队 12–20px），否则又回到"比例混乱"。

## 6. 与引擎 / 管线相关的风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 🟡 **线宽恒定 vs zoom** | 要把线宽从"世界 px 固定"改为"屏幕 px 恒定（÷zoom）"，否则缩小依旧糊 | 在 Pixi 绘制时用 `width = k / zoom`；需程基岩配合，`hex_map_version` 变更时按当前 zoom 重建 |
| 🟡 **地形 LOD 需监听 zoom** | 目前 Pixi 层只在 `hex_map_version` 变化时重建，**不随 zoom 重建** | 增一个"zoom 跨档位"门控（0.30 / 0.55 两档），跨档才重建地形层；档内不重建 |
| 🟡 **领土 alpha 下调后 ΔE 重算** | 0.42→0.30 会改变所有势力的合成色 | 用项目已有 ΔE 脚本在"叠底后"重跑，确保相邻 ≥18 |
| 🟡 **格网描边开销** | 给 2.4 万格加 `stroke` 会增加一次 Pixi 路径描边（比纯 `fill` 贵） | 与地形**同一次 `Graphics` 构建**、`hex_map_version` 门控；`zoom<0.18` 关掉全局网 A、只留领土网 B；实测 GPU 自适应分辨率下影响有限 |
| 🟢 **新增图标体积** | 均为 SVG、可内联 | 与现有 10 个走同一 Vite import 机制；**计入 `AttributionBar.tsx` 的 CREDITS**（CC BY 3.0 必须可见署名） |
| 🔴 **`mask-image` 的 `url()` 未加引号 → 图标渲染成方块** | **已实锤（2026-10-04 复验）**：Vite 内联 <4KB SVG 为 data URI 时含引号，`url(${x})` 非法 → `mask-image` 被丢弃 → 只剩背景色方块。影响了 CityMarker / ArmyMarker / BattleOverlay / CityCard / ShortcutHelp | 见 **§4.8.1**：统一 `url("${x}")` + `build.assetsInlineLimit: 0` + 把 3 份重复 `maskStyle()` 收敛成单一 `maskUrl()` helper |
| 🔴 **交战前线（L4）依赖 `at_war` 数据** | 需后端在 hex/势力态里给出"是否交战" | **需经主理人向程基岩确认字段是否存在**；不存在则 L4 降级为"仅进攻箭头的势力色" |
