## 一、什么是确定性游戏

### 1.1 定义
相同的初始状态 + 相同的输入序列 = 完全相同的游戏结果。

### 1.2 为什么重要

| 场景 | 价值 |
|------|------|
| **多人游戏** | 所有客户端看到相同的结果，不需要同步每帧状态 |
| **回放系统** | 可以精确复现任何一局游戏 |
| **调试** | bug可以稳定复现，不会"时有时无" |
| **反作弊** | 可以校验客户端状态是否合法 |
| **测试** | 测试结果稳定，不会随机失败 |
| **AI训练** | 相同条件下可以对比不同AI的表现 |

## 二、确定性的三大敌人

### 敌人1：随机数
**问题**：到处用random，结果不可控。

**解决方案**：
- 统一的随机数生成器
- 基于seed初始化
- 所有随机数都从这里取
- 记录随机数调用次数

### 敌人2：执行顺序
**问题**：并发、事件顺序不确定，导致结果不同。

**解决方案**：
- 单线程游戏逻辑
- 固定的处理顺序（比如按势力ID排序）
- 所有玩家同时决策，同时执行
- 战斗同时结算，不是一个一个来

### 敌人3：外部依赖
**问题**：时间、网络、文件等外部因素影响结果。

**解决方案**：
- 不用真实时间，用游戏内的回合数
- 不依赖外部API的返回顺序
- 所有输入都是确定的

## 三、如何实现确定性

### 3.1 统一的随机数生成器

```python
class GameRandom:
    def __init__(self, seed: int):
        self.seed = seed
        self.rng = random.Random(seed)
        self.call_count = 0  # 记录调用次数，便于调试

    def randint(self, a: int, b: int) -> int:
        self.call_count += 1
        return self.rng.randint(a, b)

    def choice(self, seq: list) -> any:
        self.call_count += 1
        return self.rng.choice(seq)
```

**关键点**：
- 全局只有一个实例
- 所有随机数都从这里取
- 禁止直接使用random模块

### 3.2 固定的执行顺序
- 回合处理的步骤顺序固定
- 势力处理顺序固定（按名称排序）
- 战斗结算顺序固定
- 事件处理顺序固定

### 3.3 状态快照与校验
- 每回合结束保存状态快照
- 计算状态哈希
- 可以对比不同运行的结果是否一致

## 四、确定性与可复现性

### 4.1 回放实现
只需要记录：
- 初始seed
- 所有玩家的输入（命令序列）
- 不需要记录每帧的状态

**优点**：
- 回放文件很小
- 可以精确复现
- 可以用来做bug报告

### 4.2 调试技巧
- 出问题时保存seed和命令序列
- 用相同的seed重放，稳定复现
- 可以在关键位置加断点
- 可以对比调用次数，看哪里不一样

## 五、常见误区

### 误区1：确定性 = 没有随机性
不对。确定性只是说"相同的随机种子产生相同的随机序列"，游戏里还是可以有随机事件，只是可复现。

### 误区2：只有多人游戏需要确定性
不对。单机游戏也需要：
- 调试方便
- 测试稳定
- 可以回放
- 可以做AI对比

### 误区3：确定性会限制游戏设计
不对。大部分回合制策略游戏都可以做成确定性的，玩家感觉不到区别。
