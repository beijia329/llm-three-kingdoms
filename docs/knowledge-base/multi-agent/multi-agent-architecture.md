## 一、多智能体拓扑分类

### 1.1 常见拓扑结构

| 拓扑 | 特点 | 适用场景 |
|------|------|---------|
| **Chain链式** | 一个接一个，顺序传递 | 流水线式任务 |
| **Star星型** | 中心协调者，多个执行者 | 有明确领导的团队 |
| **Mesh网状** | 全连接，任意两个都能通信 | 平等协作的团队 |
| **Tree树形** | 层级结构，上下级 | 复杂的组织架构 |
| **Dynamic动态** | 拓扑随任务变化 | 灵活的自适应系统 |

### 1.2 本项目的拓扑
我们采用的是**星型+并行**的混合拓扑：
- GameEngine是中心，协调所有玩家
- 三个玩家（魏蜀吴）并行决策
- 玩家之间通过Engine间接通信（外交消息）
- 玩家不直接修改游戏状态，只能发命令

## 二、三层协同架构（游戏NPC）

### 2.1 架构图
```
┌─────────────────────────────────────┐
│         感知层（Perception）        │
│  - 收集环境信息                      │
│  - 过滤和预处理                      │
│  - 形成观察数据                      │
└───────────────┬─────────────────────┘
                │
                ▼
┌─────────────────────────────────────┐
│         认知层（Cognition）         │
│  - 记忆管理                          │
│  - 推理决策                          │
│  - 规划与反思                        │
└───────────────┬─────────────────────┘
                │
                ▼
┌─────────────────────────────────────┐
│         行动层（Action）            │
│  - 动作生成                          │
│  - 动作校验                          │
│  - 执行与反馈                        │
└─────────────────────────────────────┘
```

### 2.2 感知层
**职责**：从游戏环境中收集信息，形成AI能理解的观察数据。

**关键功能**：
- 信息过滤：只给AI需要知道的信息
- 信息迷雾：不同位置看到的信息不同
- 数据序列化：把游戏状态转成文本/表格

**对应我们的设计**：
- GameObservation 类
- 信息迷雾机制
- 状态序列化优化

### 2.3 认知层
**职责**：根据观察数据做出决策。

**关键功能**：
- 记忆系统：短期/中期/长期记忆
- 推理：分析局势、制定策略
- 规划：多步规划、目标分解

**对应我们的设计**：
- MemoryManager 记忆管理器
- Prompt中的思维链引导
- 历史决策记录

### 2.4 行动层
**职责**：把决策转化为游戏可执行的动作。

**关键功能**：
- 动作生成：把自然语言决策转成结构化命令
- 动作校验：检查动作是否合法可行
- 执行反馈：执行后获取结果，用于学习

**对应我们的设计**：
- OutputParser 输出解析器
- 五层防御体系
- Command模式 + VAP协议

## 三、可验证动作协议（VAP）

### 3.1 什么是VAP
Verifiable Action Protocol，可验证动作协议。

将LLM的自然语言输出，通过多层校验，转化为游戏引擎可以**安全执行**的指令。

### 3.2 为什么需要VAP
- LLM输出不可靠，不能直接执行
- 需要保证游戏状态的一致性
- 需要防止非法操作破坏游戏
- 出了问题可以定位是哪一层的问题

### 3.3 三层校验

#### 第一层：语法校验
- 是不是合法的JSON？
- 格式对不对？

**工具**：json_repair, 正则提取

#### 第二层：Schema校验
- 字段对不对？
- 类型对不对？
- 枚举值对不对？

**工具**：Pydantic, Zod

#### 第三层：业务校验
- 当前状态下能不能执行？
- 资源够不够？
- 目标存在吗？
- 距离够不够？

**工具**：游戏引擎的状态检查

### 3.4 VAP的好处
- **安全**：LLM不能执行非法操作
- **稳定**：不会因为输出格式错而崩溃
- **可调试**：哪一层失败了一目了然
- **可统计**：可以统计各层的失败率
- **可扩展**：增加新命令很方便

## 四、记忆系统设计

### 4.1 记忆分层

| 层级 | 时间跨度 | 内容 | 用途 |
|------|---------|------|------|
| **瞬时记忆** | 当前回合 | 观察数据、思考过程 | 当次决策 |
| **短期记忆** | 最近5-10回合 | 完整的回合历史 | 近期局势分析 |
| **中期记忆** | 整局游戏 | 摘要、关键事件 | 整体战略调整 |
| **长期记忆** | 跨局游戏 | 经验、教训、策略偏好 | 持续学习优化 |

### 4.2 记忆管理策略
- **滑动窗口**：短期记忆只保留最近N回合
- **摘要压缩**：中期记忆是短期记忆的摘要
- **重要性筛选**：重要事件优先保留
- **定期总结**：每10回合做一次战略总结

### 4.3 记忆的组织方式
- 按时间顺序：回合1, 回合2, ...
- 按类型：事件、决策、结果
- 按重要性：关键事件、普通事件

## 五、多智能体通信

### 5.1 通信方式
- **间接通信**：通过环境/中介传递消息
- **直接通信**：Agent之间直接发消息
- **广播通信**：一个发，所有都能收到

### 5.2 我们的外交系统
- **消息传递**：每回合可以发1条消息
- **流言系统**：可以散布流言影响对方
- **间接影响**：通过行动传递信号（比如调兵）

### 5.3 通信的挑战
- 可信性：对方说的话是不是真的？
- 理解：能不能正确理解对方的意图？
- 承诺：对方答应的事会不会兑现？
