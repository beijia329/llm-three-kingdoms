## 一、什么是游戏平衡

### 1.1 定义
游戏平衡是指游戏中各个选项、策略、角色之间的相对强度合理，没有明显的最优解，玩家有多种可行的玩法选择。

### 1.2 平衡的三个层次

| 层次 | 说明 | 例子 |
|------|------|------|
| **数值平衡** | 单个数值的合理性 | 征兵1个兵花多少钱 |
| **系统平衡** | 各个系统之间的平衡 | 经济发展 vs 军事扩张 |
| **策略平衡** | 各种玩法策略的平衡 | 速攻流 vs 龟缩流 vs 经济流 |

### 1.3 为什么平衡重要
- 不平衡 = 只有一种最优玩法 = 无聊
- 不平衡 = 新手被老玩家虐 = 流失
- 不平衡 = 竞技性差 = 没有讨论价值

## 二、平衡性的核心原则

### 原则1：没有最优解
玩家应该有多种可行的策略选择，每种策略都有优缺点。

**反例**：速攻流胜率80%，那所有人都速攻，游戏就没意思了。

### 原则2：风险与收益对等
高风险的策略应该有高收益，低风险的策略收益也低。

**例子**：
- 速攻：风险高（失败就崩了），收益高（成功就滚雪球）
- 龟缩：风险低（不容易被打），收益低（发展慢）

### 原则3：选择有意义
玩家的每个决策都应该对结果有影响，不能选什么都一样。

**反例**：发展经济和发展军事效果差不多，那玩家随便选就行，没有策略感。

### 原则4：可理解
玩家应该能理解为什么输了、为什么赢了，而不是感觉"这游戏全靠运气"。

## 三、三方对战的特殊平衡问题

### 3.1 二打一问题
三方对战中，最常见的不平衡是两个弱的联合起来打最强的。

**影响**：
- 最强的那个总是被针对
- 导致"领先惩罚"
- 玩家不敢发展太快

**解决方案**：
- 外交系统（可以谈判、可以背叛）
- 胜利条件多样化（不只是占地最多）
- 适当的领先优势（但不要太夸张）

### 3.2 历史先验问题
LLM扮演的AI可能有历史刻板印象：
- 蜀吴联合打魏（三国演义的影响）
- 某些"名将"特别强
- 某些策略被认为是"正确"的

**解决方案**：
- System Prompt强调"这是游戏，不用遵从历史"
- 初始设置尽量平衡
- 测试时用同模型扮演三方，排除模型差异

### 3.3 外交的影响
信使系统增加了策略深度，但也增加了平衡难度：
- 会不会出现"嘴炮无敌"？
- 流言会不会太强？
- 联盟会不会太稳定？

## 四、平衡性测试方法

### 4.1 自对战测试
用同一个模型扮演三方，看胜率分布。

**优点**：
- 排除模型差异的影响
- 纯看游戏规则的平衡性

**缺点**：
- 真实对战中模型能力不同
- 可能和实际情况有差距

### 4.2 交叉对战测试
不同模型互相打，看综合胜率。

**优点**：
- 更接近真实情况
- 可以测试不同模型的策略风格

**缺点**：
- 结果受模型能力影响大
- 难以区分是模型强还是游戏不平衡

### 4.3 极端策略测试
用专门的脚本AI测试各种极端策略。

**为什么重要**：
- 正常AI可能不会用极端策略
- 但玩家会用
- 极端策略无敌 = 游戏毁了

**常见极端策略**：
- 全经济流
- 速攻流
- 龟缩流
- 流言流
- 集中兵力流

### 4.4 参数扫描
系统地调整关键参数，观察胜率变化。

**步骤**：
1. 找出影响最大的几个参数
2. 每个参数取几个不同的值
3. 每个值跑N局测试
4. 画出参数 vs 胜率的曲线
5. 找到平衡点

## 五、平衡性调优技巧

### 5.1 小步调整
每次只调一个参数，每次调整幅度不要太大。

**为什么**：
- 调太多不知道哪个起作用
- 容易调过了
- 便于回滚

### 5.2 关注边际效应
参数不是线性的，越接近极端，调整的影响越大。

**例子**：
- 城墙倍率从1.0调到1.1，胜率变化可能不大
- 城墙倍率从1.5调到1.6，胜率变化可能很大

### 5.3 不要追求完美
绝对平衡是不可能的，也没必要。

**可接受范围**：
- 三方胜率：25%-40%
- 不是某一方必胜就行
- 玩家可以通过策略弥补差异

### 5.4 平衡是动态的
游戏在变，玩家在进步，平衡也要跟着调。

- 新功能可能打破平衡
- 玩家发现新策略可能打破平衡
- 平衡调优是持续的过程

## 六、常见的平衡陷阱

### 陷阱1：防守方太强
**现象**：大家都龟缩，没人愿意进攻，游戏变成比谁发展快。

**原因**：
- 城墙太强
- 守军有加成
- 进攻方消耗大

**解决方案**：
- 降低城墙加成
- 增加围城的收益（比如断粮）
- 增加进攻方的战术选择

### 陷阱2：初始优势太大
**现象**：开局好的一方一直领先，很难翻盘。

**原因**：
- 资源滚雪球
- 胜利方获得太多资源
- 失败方损失太大

**解决方案**：
- 减少胜利方的收益
- 增加失败方的恢复能力
- 增加随机事件，增加变数

### 陷阱3：某种策略无敌
**现象**：所有人都用同一种策略，游戏变成比谁执行得好。

**原因**：
- 某个系统太强
- 其他策略太弱
- 没有克制关系

**解决方案**：
- 削弱OP策略
- 增强其他策略
- 增加克制关系

### 陷阱4：运气成分太大
**现象**：玩家感觉输赢全靠运气，自己的决策没用。

**原因**：
- 随机因素太多
- 随机事件影响太大
- 策略的影响被运气淹没

**解决方案**：
- 减少随机因素
- 增加策略的权重
- 让玩家有办法应对坏运气

## 七、对本项目的启示

### 7.1 我们的平衡目标
- 三方胜率在25%-40%之间
- 平均游戏时长20-30回合
- 至少有3种可行的策略
- 进攻/防守胜率接近50/50
- 没有明显的OP策略

### 7.2 关键平衡参数
- 城墙强度
- 士气影响
- 资源产出
- 征兵成本
- 行军速度
- 流言效果
- 将领属性

### 7.3 测试计划
1. 先用简单AI跑自对战，看大致平衡
2. 调参数，让胜率在可接受范围
3. 测极端策略，确保没有OP
4. 上LLM测试，看真实表现
5. 根据结果再调优
