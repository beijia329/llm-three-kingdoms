## 一、核心理念

### 1.1 Methodology-First Adoption
先建立结构化方法论，再引入AI工具。开发者在学习工具使用的同时掌握框架原则，从一开始就能产出一致的优质结果。

**学习曲线**：约2-4周达到熟练水平。

### 1.2 企业级 vs 个人级

| 维度 | 个人项目 | 企业级 |
|------|---------|--------|
| 工作流 | See→Say→Run→Fix | Spec→Context→TDD→Review→CI/CD |
| AI角色 | 协作伙伴 | 受控执行者 |
| 人角色 | 引导者 | 架构师 + 审查者 |
| 质量保障 | 人工检查 | 测试 + 审查 + CI |

## 二、标准五步工作流

### 第一步：探索（Explore）
- 理解现有代码库结构
- 阅读相关文档
- 确认依赖和约束
- 明确任务目标

**产出**：对任务的清晰理解

### 第二步：规划（Plan）
- 列出要创建/修改的文件
- 设计关键函数签名
- 考虑边界情况和错误处理
- 规划测试用例

**产出**：清晰的实现计划

### 第三步：执行（Execute）
- 按计划写代码
- 小步前进
- 遵循编码规范
- 不做计划外的重构

**产出**：可运行的代码

### 第四步：验证（Verify）
- 跑单元测试
- 跑集成测试
- 检查代码规范
- 验证边界情况

**产出**：通过验证的代码

### 第五步：提交（Commit）
- 确认所有测试通过
- 确认代码符合规范
- 写清晰的提交信息
- 代码审查（可选）

**产出**：合入代码库的提交

## 三、关键工程护栏

### 3.1 CLAUDE.md / AGENTS.md
根目录规范文件，AI每次启动自动读取。

**必备内容**：
1. **编码规则**（8-10条不可妥协项）
2. **文件结构**（目录布局映射）
3. **数据库Schema**（关键表和关系）
4. **API模式**（端点命名、响应格式、错误处理）
5. **安全规则**（验证、认证、密钥管理）

**效果**：
- 减少73%的代码审查驳回率
- 减少45%的bug

### 3.2 测试驱动开发（TDD）
核心逻辑必须先写测试再写实现。

**TDD三步循环**：
1. **红**：先写测试，确认失败
2. **绿**：写实现，让测试通过
3. **重构**：优化代码，保持测试通过

## 四、团队协作最佳实践

### 4.1 任务隔离
- 每个任务一个 worktree + 一个 Claude 会话
- 只做一件事，保持上下文干净
- 复杂任务先做计划，用第二会话审核计划

### 4.2 主会话与子代理
- 主会话保持干净，只做核心开发
- 阅读/调研/测试设计丢给 subagents
- 避免上下文污染

### 4.3 计划模式
复杂任务先进入 Plan Mode，让AI输出：
- 将创建或编辑哪些文件
- 将引入哪些函数签名
- 有哪些边界情况和错误处理

## 五、常见陷阱

### 5.1 不要让AI自主规划
- AI规划容易失控，范围蔓延
- 人来制定计划，AI来执行
- 计划要拆到可验证的小步骤

### 5.2 不要跳过验证
- 每步完成都要有验证标准
- 不要攒到最后一起测
- 小步验证，及时发现问题

### 5.3 不要全局重构
- 重构容易引入新bug
- 小步修改，确认后再改下一处
- 有测试兜底再重构

---

## 六、对本项目的启示

1. ✅ 采用五步工作流（探索→规划→执行→验证→提交）
2. ✅ 用AGENTS.md作为项目规范文件
3. ✅ 核心逻辑采用TDD
4. ✅ 小步前进，每步都有验收标准
5. ✅ 人做架构设计，AI按规范执行
