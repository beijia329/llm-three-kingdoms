## 一、为什么需要 AGENTS.md

### 1.1 问题
- AI写代码质量不稳定
- 风格漂移，每个文件写法不一样
- 重复造轮子
- 违反项目约定
- 安全漏洞

### 1.2 解决方案
根目录放一个规范文件，AI每次启动自动读取。

**研究数据**：
- 完善的CLAUDE.md可减少73%的代码审查驳回率
- 减少45%的bug
- 大幅提升代码一致性

## 二、必备内容（5大模块）

### 模块1：编码规则（Coding Rules）
**8-10条不可妥协的规则**，写得越具体越好。

**示例**：
```
- 使用 TypeScript，严格模式
- 变量用 camelCase，类名用 PascalCase
- 所有函数必须有类型注解
- 不使用 any 类型
- 错误处理必须明确
- 不写超过50行的函数
```

**原则**：
- 不要写"遵循最佳实践"这种空话
- 要写具体的、可检查的规则
- 8-10条足够，太多了AI记不住

### 模块2：文件结构（File Structure）
把目录布局映射清楚，让AI知道文件该放哪。

**示例**：
```
src/
├── components/     # React组件，每个组件一个文件夹
├── hooks/          # 自定义hooks
├── utils/          # 工具函数
├── types/          # TypeScript类型定义
└── pages/          # 页面组件
```

**重要性**：
- 避免AI把文件放错地方
- 保持项目结构一致性
- 新AI快速理解项目结构

### 模块3：数据库Schema
关键表和关系，让AI准确操作数据。

**包含**：
- 表名和字段
- 主键、外键、索引
- 关系说明（一对多、多对多）
- 常用查询模式

### 模块4：API模式
- 端点命名约定
- 响应格式（统一的成功/失败格式）
- 错误处理约定
- 认证方式

### 模块5：安全规则
- 输入验证要求
- 认证授权机制
- 密钥管理（不能硬编码）
- SQL注入防护
- XSS防护

## 四、写作原则

### 4.1 具体，不要模糊
❌ 不好："遵循最佳实践"
✅ 好："所有函数必须有JSDoc注释，包含@param和@returns"

### 4.2 少而精，不要大而全
- 8-10条核心规则足够
- 太多了AI记不住，等于没有
- 把最重要的、最容易违反的写上

### 4.3 正面表述，不要负面
❌ 不好："不要写烂代码"
✅ 好："每个函数不超过50行，单一职责"

### 4.4 可验证
规则应该是可以自动检查的，或者人可以一眼判断的。

## 五、常见错误

### 5.1 写得太笼统
"代码要整洁" —— 什么叫整洁？每个人理解不一样。

### 5.2 写得太多
几十条规则，AI根本记不住，等于白写。

### 5.3 不更新
项目在变，规则不变，慢慢就过时了。

### 5.4 只有规则，没有例子
有例子AI理解得更准确。
